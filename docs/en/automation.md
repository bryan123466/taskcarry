# Scheduled governance in the original chat

[Three-step setup](windows-example.md) · [Maintenance reference](governance-maintenance.md)

Scheduled governance is part of standard onboarding. The assistant creates or reuses a native schedule attached to the original governance chat, using the existing runtime, source bindings, model and permissions. The ordinary starting cadence is daily; setup establishes the actual time and time zone. You can pause it or explicitly choose manual operation, with that difference recorded.

## What each scheduled turn does

It reads a bounded agenda and relevant task context, verifies changed evidence, resumes authorized unfinished operations after checking their effects, maintains project memory and saves meaningful local Git changes. It checks the official release channel and records whether a candidate is applicable, should wait, or should be declined. No new work means no fabricated task, empty commit or repeated warning.

Finding a new release does not install it. Private uploads follow their separately selected destinations and scope. The schedule does not publish anything to the TaskCarry developer repository.

## Establish the actual host connection

The assistant prepares a schedule plan and uses the host's supported native creation/readback capabilities. It reuses an existing matching schedule and preserves its original chat; it does not create a second writer or secretly substitute an operating-system timer. Missing host support remains a specific setup gap, with the next native action shown to you.

Verify the saved chat, working directory, source routes, cadence, time zone, full prompt and runtime access. Native configuration readback, a manual governance result and the first natural trigger are three separate evidence levels. Waiting for the first trigger is not a failed run. Local-file tasks require the computer and desktop app to be available; see [the host documentation](https://learn.chatgpt.com/docs/automations?surface=app).

## Durable instruction for the governance assistant

> Continue this original project governance chat from its current records and instructions. Preserve tasks, paused work, source routes and fixed runtime. Read a bounded agenda and relevant task context; check actual effects before resuming any operation. Work only within existing authorization. Maintain sourced project memory and precise local Git saving, preserving unrelated files and index/worktree state. Read the selected official release channel, assess applicability and explicitly record the result; do not install a candidate merely because it exists. Report meaningful changes, actual receipts, pending conditions and useful next steps. Do not manufacture work, repeat completed history, create another schedule or send unrequested cross-chat messages.

The installed daily-governance Skill supplies the detailed procedure. TaskCarry's local record tools do not themselves wake an AI, grant host permissions or prove a naturally delivered heartbeat. Other hosts require their own native capability verification.
