# Getting started: connect your project progress and working chats

[Main onboarding guide](windows-example.md) · [Daily-operation index](operation-manual.md) · [Manual fallback](manual-setup.md) · [简体中文](../zh-CN/getting-started.md) · [繁體中文](../zh-TW/getting-started.md)

Already working in Codex? Keep your project and conversations. TaskCarry adds a durable record of tasks, results, effective decisions and where to continue. This page introduces the published **0.2.0rc6 prerelease** workflow. Download the [RC6 product package](https://github.com/bryan123466/taskcarry/releases/tag/v0.2.0rc6) and follow the [corrected onboarding guide](windows-example.md).

<a id="prepare-the-directories-and-two-project-inputs"></a>

## Start from your existing project

Create an independent governance chat in a separate governance folder, or return to an already verified TaskCarry governance chat. Give it a project locator and the selected product's extraction directory, then send the [one onboarding prompt](windows-example.md#install). It installs or reuses the tool, inherits known work and guides the remaining host actions. You do not need to learn control IDs, branches or commands first.

An empty governance folder does not imply an empty business project. Keep prior deliverables, decisions, task identities and WIP. If you are starting a genuinely new project within Codex, the same conversation can establish goals and an appropriate first baseline.

<a id="add-specialists-when-needed"></a>

## Keep useful work arrangements

Governance first checks existing chats and responsibilities. Additional specialists may be zero; add them only for useful parallel outputs and clear write ownership. Keep working directly in original chats. Governance maintains memory and evidence; ongoing project coordination is an optional role, not a condition for using the toolkit.

The host AI reads relevant permitted sources. It cannot assume access to every old chat. If a capability is missing, it gives the exact current action; the [manual fallback](manual-setup.md) supplies commands and transfer prompts only when needed.

## After connection

Ask to continue the last unfinished task, save a meaningful stopping point, or see connected progress. Working chats read their task and relevant effective decisions; they save selected outputs and next steps at meaningful boundaries. Understanding drafts remain distinct from confirmed decisions. Shared progress does not automatically merge all code.

Successful onboarding shows inherited context, actual runtime and per-window connection evidence, the current checklist and next step. Generated MCP files are not proof that native tools loaded. Checkpoints, deliveries, reception, adoption and business acceptance remain separate.

Scheduling, private remotes and other hosts/computers are optional. Returning to a project resumes its records; it does not reinstall or create duplicate tasks. Follow the [main guide](windows-example.md) for the complete path.
