# 回到原治理窗口的定时治理

[三步接入](windows-example.md) · [维护参考](governance-maintenance.md)

定时治理属于标准接入。总控通过宿主原生能力建立或复用绑定本原窗口的任务，沿用真实运行环境、状态来源、模型和权限。通常每日一次，接入时确定实际时间与时区。你保留暂停权，也可以明确选择手动使用，报告会保留这一差异。

## 每次到点做什么

有限读取当前事项和相关任务上下文，核对有变化的证据；中断操作先确认实际效果，再在既有授权内续办。维护有效项目记忆，对有意义的本地 Git 变化精确保存；读取选定官方发行通道，判断优先采用、计划采用、维持当前、等待条件或拒绝候选。无变化不造任务、空提交或重复提醒。

发现新版不会直接安装。私有上传遵循用户已经选定的目的地和范围，也不会向 TaskCarry 开发者的开源仓库发布内容。

## 核对实际宿主配置

总控准备调度计划，通过宿主支持的原生创建和回读完成接入。复用匹配的现有任务，保留原聊天；不增加重复写入者，也不暗中换成系统定时器。宿主能力未开放时，列出具体缺步和当前原生操作。

验收包括保存的聊天、目录、状态路由、频率、时区、完整提示词和运行环境可达性。配置回读、手动治理、第一次自然触发分别留证，等待触发不算失败。本地文件任务需要电脑和桌面应用可用，实际条件见[宿主官方说明](https://learn.chatgpt.com/docs/automations?surface=app)。

## 给治理助手的耐久指令

> 接续本原项目治理窗口，读取当前有效记录与指令，保留任务、暂停位置、状态来源路由和固定运行环境。有限读取 agenda 与相关任务 context；恢复操作前核对实际效果，只在已有授权内推进。维护有来源的项目记忆和本地 Git 精确保存，保全无关文件与暂存/工作区状态。读取已选官方发行通道，评估适用性并明确保存结果；不能因为发现候选就安装。报告实质变化、实际回执、下一条件和有用建议，不制造任务、不重复已完成历史、不另建调度，也不发送未授权的跨对话消息。

已安装的日常治理 Skill 提供具体方法。TaskCarry 本地记录工具不自行唤醒 AI、不授予宿主权限，也不能用工具存在证明自然 heartbeat 已送达；其他宿主仍需各自的原生能力验收。
