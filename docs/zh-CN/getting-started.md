# 开始使用：把项目进度和工作窗口接起来

[接入主手册](windows-example.md) · [日常操作索引](operation-manual.md) · [手动后备](manual-setup.md) · [English](../en/getting-started.md) · [繁體中文](../zh-TW/getting-started.md)

已经在 Codex 中推进项目？保留项目与对话，TaskCarry 增加任务、成果、有效决定和接续位置的持久记录。按你的情况选择[首次安装](windows-example.md)或[更新已有安装](updating.md)。

<a id="准备目录和两项项目输入"></a>

## 从现有项目出发

在独立治理目录新建治理窗口，已有有效 TaskCarry 治理窗口则复用。给出项目定位线索和选定产品的解压位置，发送[一条接入提示词](windows-example.md#install)。它会安装或复用工具、继承已有工作，并带着完成剩余宿主操作；无需先学习 control ID、分支或命令。

空治理目录不等于空业务项目。原成果、决定、任务身份和 WIP 继续保留。确实是在 Codex 中启动新项目时，同一对话也可以梳理目标并建立适当起点。

<a id="按需要加入专业窗口"></a>

## 保留有用的工作安排

治理先检查已有窗口与职责。新增专业窗口可以为零，只有并行成果和清楚的写入归属确有价值时才增设。继续直接在原工作窗口推进；治理负责记忆与证据，长期项目协调是可选职责，不是使用条件。

宿主 AI 定向读取获准来源，不假设能够访问所有旧聊天。缺能力时给出当前准确一步；[手动后备](manual-setup.md)只在需要时提供命令和转交提示词。

## 接入后怎样运行

可以要求继续上次未完成任务、保存有意义的暂停位置或查看已接入进度。工作窗口读取自己的任务和相关有效决定，在工作节点保存选定成果与下一步；理解候选与确认决定保持区分。共享进度不会自动合并所有代码。

接入结果应说明继承的上下文、实际运行时和逐窗口连接证据、当前清单与下一步。生成 MCP 文件不代表原生工具已经加载。checkpoint、交付、接收、采用和业务验收分别记录。

定时任务、私有远端及其他宿主/电脑均为可选项。再次返回时从记录接续，不重新安装或重复建任务。完整路径统一见[主手册](windows-example.md)。
