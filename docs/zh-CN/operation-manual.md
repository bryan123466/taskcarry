## 推荐的一条接入路线

为现有项目建立独立治理窗口，已有有效 TaskCarry 治理窗口/control 则复用。发送[一条接入提示词](windows-example.md#install)，由治理继承项目上下文、安装或复用工具，并带领完成剩余连接；用户不必先决定技术 ID 或专业窗口数量。

治理与记忆是默认职责。首次项目梳理帮助接入；临时或长期项目协调由用户选择。继续直接在原主窗口或专业窗口工作，调整协调偏好时保留同一记忆与任务身份。新增专业窗口可以为零。

助手读取获准的相关证据，说明缺失历史；候选理解与建议不替代已确认的有效决定。空治理目录不代表新业务项目，历史成果与 WIP 保留在实际位置。

## 谁负责什么

| 对象 | 职责 |
|---|---|
| 用户 | 项目方向、业务决定、验收及需要授权的动作。 |
| 治理窗口 | 维护项目记忆与证据，复核已接入进展，按计划接收明确阶段；按选择兼任项目协调。 |
| 工作窗口 | 读取相关有效决定、推进任务、保存有意义的进展并精确交付稳定阶段。 |
| 接收基线 | 用于接收阶段的独立干净 Git 工作区，不混入专业 WIP。 |
| TaskCarry 引擎 | 持久记录、核对条件，执行已支持的保存、接收、采用与恢复操作。 |
| 宿主 | AI 理解、实际聊天读取/创建、配置加载、权限与原生定时能力。 |

每个任务和写入范围保留一个主要写入者；其他窗口可只读复核或承担明确不重叠的子任务。聊天分开不等于工作区已隔离，调整前检查真实归属与活跃写入者。

<a id="continuation"></a>

## 一次完整盘点与日常接续

工作窗口接续前读取当前任务、相关最新检查点和有效决定；在有意义的成果、决定变化或暂停处，保存任务所属的选定文件、发现、来源和下一步。治理用这些记录维护共同理解，只补读有变化或缺失的相关上下文。旧聊天访问能力另行核对，没有自动全历史监控。

理解候选保留来源与版本，相关修订确认后才更新有效稿，同时保留先前版本并指出受影响任务。这套方法复用项目文件及 task/checkpoint/artifact，不另造决定数据库或任务条件修订 API。

<a id="evidence"></a>

### 理解每种结果证明什么

| 情况 | 相应记录或操作 |
|---|---|
| 旧成果已在可信基线中 | 保留来源与纳入事实，不再次排队。 |
| 未完成或未提交工作 | 保存 checkpoint 和准确接续点，不称为交付。 |
| 稳定、明确的 Git 阶段 | 核对 base、commit、任务和完整路径，先预览接收计划再执行。 |
| 原有普通资料 | 保留选定文件与来源；后续工作窗口仍完成标准 Git 配置。检查点不提供通用非 Git 交付/接收。 |
| 暂停、等待或未变化任务 | 保留当前位置，不制造提醒或新积压。 |
| 任务确需已接收代码 | 按实际依赖预览采用，保留本地提交/index/worktree/新文件；只读取进度无需合并。 |
| 操作中断 | 核对实际效果和原身份，补齐支持的缺步。 |

地图和说明描述项目，工具记录与实际文件证明效果。保存、交付、接收、采用和业务验收分别判断，记录材料路径也不等于已验证备份。

<a id="connection"></a>

## MCP、CLI 和定时治理的区别

MCP 让宿主 AI 直接调用内核动作；原生工具不可用时，固定运行时的隔离 CLI 继续绑定同一 control。两者均无需另配模型服务。接入文件生成、宿主加载与原生 doctor/status 调用分别提供证据，各工作台核对自己的实际包来源与绑定。

已登记工作台的 setup 可将四项 Skills 和接入材料写到宿主工作目录，仍绑定原 control。`target`、`workspace`、`task_id` 一起提供并按既有登记核对，不初始化第二 control。生成片段用隔离 UTF-8 启动固定选定包，合并生效配置时保留它；详见[手动绑定与验收](manual-setup.md#mcp)。

## 标准本地治理与任务接续

完整接入包括本地治理 Git、持续工作窗口的实际任务/目录/Git 关联、各窗口原生连接验收、原治理窗口调度配置及回读、一次官方更新检查。私有远端和网盘可选；只作历史来源的对话无需活跃工作区。外部大文件列明引用与备份覆盖，记录路径不等于保存了实体。

一个现实项目可以跨目录、仓库和已有状态来源。保留路由和局部身份，每个来源仍只绑定一条接收基线。共享上下文或维护工具不合并业务分支，也不形成跨库事务。
