# 更新与接续：保留原来的治理和工作

[首次安装](windows-example.md) · [维护说明](governance-maintenance.md) · [技术合同](../GOVERNANCE_API.md)

## 先判断你已有哪种治理

| 当前情况 | 如何接续 |
|---|---|
| 已安装 TaskCarry | 继续使用原治理目录、任务及历史；评估当前包、能力方法和项目规则，只更新适用部分。 |
| 使用其他治理工具 | 先只读理解既有规则、决定、任务与保存方式，确认哪些内容要接入 TaskCarry。保留原工具和数据；继承资料不等于升级、卸载或自动迁移第三方系统。 |
| 只有一个治理对话 | 在原对话保留有效决定与未完成工作，补齐真实工作位置、项目记忆、本地保存和工具连接；不要求重新讲完所有历史。需要独立治理目录时保留原对话来源。 |

不确定属于哪一种时，在原治理对话发送：

> 请先检查我们现有的治理、工具和项目工作，告诉我属于已有 TaskCarry 更新、其他治理工具接续，还是治理对话补齐配置。保留有效规则、决定、任务、历史和未完成工作，不重新初始化已有项目。按你读到的 TaskCarry 接入方法，给出最小必要的接续计划，带我完成缺少的步骤，并说明实际完成结果。

只有治理对话、尚无产品时，先按[首次安装的目录准备](windows-example.md)取得套件；由治理读取当前工作目录下 toolkit 的产品入口。若有多个可疑状态来源，先说明差异再选择，不创建第二份状态来掩盖不明确的绑定。

## 从其他工具或治理对话接续

先确认项目及允许读取的范围，再继承有来源的目标、成果、决定、职责和未完成位置。工具接口能读到什么、历史读取了多少，都应明确。需要你转交旧窗口信息时，只提供最小交接提示词。

治理随后按三步手册补齐本地 Git、实际工作位置、同一治理来源的连接、首次治理、恢复验证和原对话日常调度。原有工具不受 TaskCarry 包更新支配；确需跨系统迁移、停用或替换时，另给具体方案，不把这类动作混入普通接入。

## 已安装 TaskCarry：在原治理窗口完成更新

继续使用原治理目录和窗口。需要升级 TaskCarry 时，可发送下面的维护提示词：

> 按我选择的通道检查已登记的官方发行来源。我提供了产品包时先核对精确身份。比较发行说明、实际运行包、已安装 Skills/方法和我的项目规则，说明适用变化、兼容性及最小必要更新。发现新版本不等于授权安装。
>
> 在本次已授权更新范围内，保留原 control/source 身份、任务、检查点、事实、决定、窗口、定制配置、Git 暂存区和未完成工作。包变更使用独立候选运行时，保留可恢复的旧安装。先预览精确受管文件/配置修改，保全定制内容，再逐个核验受影响原生连接。
>
> 用完整建制 profile complete_v1 对照既有证据。保留旧验收记录及其原含义，不把旧记录改名冒充新 profile。复用仍适用证据，补齐身份、来源理解、工作台消费、首次整轮、恢复演练和日常时段配置缺口。旧项目仍用本地路径身份时，先给明确 identity 计划再采用，保留旧来源别名及记录。不为刷新记忆初始化另一 control 或合并业务分支。
>
> 调整调度前保留有效原绑定，与我核对一个报告加一到两个吸收时段的准确安排，不重复创建。自然触发、原聊天 AI 执行和实际报告送达分别验证。中断先查已有效果，只补缺步。最后报告改变了什么、什么仍可继续、验证结果、排除项和当前真正必要的一步。

治理日常读取已登记官方通道。离线表示远端状态未知；内容没变不重复维护。稳定版或候选版按你的明确通道选择；同版本名但包哈希不同，需要身份复核。

Core 更新、能力/方法更新和用户项目决定分别管理。公开发行、本机安装、受管文件发布、运行中宿主加载是不同回执。

中断后说：**“继续原 TaskCarry 更新，核对已完成效果，只完成剩余计划。”** 版本差异放在[发行说明](../RELEASE_0.2.0.md)，预期结果见[反馈示例](user-feedback-examples.md)，确有缺步才用[手动后备](manual-setup.md)。

## 更新时如何确认记忆接续

让原治理窗口核对原任务、决定、来源及最新检查点。在独立候选环境和授权的状态副本上，完成整项目备份、清单校验与独立目录恢复，检查选定产物及历史关系；恢复副本先保持待机。需要显式索引更新时，核对原证据保留。用户不需要修改数据库标记或重新初始化项目。

治理方法、项目规则和 Core 包分别评估。某个候选包不适用时，继续使用已验证的运行组合，说明受影响功能与下一条件；无关治理优化和专业工作可以继续。换包、受管配置更新、原生窗口加载及本地问题消除分别报告。回退必须保留切换后的新增事实，旧数据库不能直接覆盖当前记录。

## 发现新版后，用户会收到什么

治理会先说明这次更新对当前项目的用途，再给出具体维护方案，请你选择现在维护、安排稍后或跳过。确认后保留原项目记忆与工作窗口，分别核验安装和原生加载。完整过程及可给原治理的接续提示见[RC8 维护流程补充](core-update-maintenance.md)。
