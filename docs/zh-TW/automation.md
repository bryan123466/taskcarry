# 回到原治理視窗的定時治理

[三步接入](windows-example.md) · [維護參考](governance-maintenance.md)

定時治理屬於標準接入。總控透過宿主原生能力建立或重用綁定本原視窗的任務，沿用真實執行環境、狀態來源、模型與權限。通常每日一次，接入時確定實際時間與時區。你保留暫停權，也可以明確選擇手動使用，報告會保留這項差異。

## 每次到點做什麼

有限讀取目前事項及相關任務上下文，核對有變化的證據；中斷操作先確認實際效果，再於既有授權內續辦。維護有效專案記憶，對有意義的本機 Git 變更精確儲存；讀取選定官方發行通道，判斷優先採用、計畫採用、維持目前、等待條件或拒絕候選。無變化不製造任務、空提交或重複提醒。

發現新版不會直接安裝。私有上傳遵循使用者已選定的目的地與範圍，也不會向 TaskCarry 開發者的開源儲存庫發行內容。

## 核對實際宿主設定

總控準備排程計畫，透過宿主支援的原生建立與回讀完成接入。重用符合的既有任務，保留原對話；不增加重複寫入者，也不暗中換成系統計時器。宿主能力未開放時，列出具體缺步與目前原生操作。

驗收包含儲存的對話、目錄、狀態路由、頻率、時區、完整提示詞與執行環境可達性。設定回讀、手動治理、第一次自然觸發分別留證，等待觸發不算失敗。本機檔案任務需要電腦與桌面應用程式可用，實際條件見[宿主官方說明](https://learn.chatgpt.com/docs/automations?surface=app)。

## 給治理助手的耐久指令

> 接續本原專案治理視窗，讀取目前有效記錄與指令，保留任務、暫停位置、狀態來源路由和固定執行環境。有限讀取 agenda 與相關任務 context；恢復操作前核對實際效果，只於既有授權內推進。維護有來源的專案記憶和本機 Git 精確儲存，保全無關檔案與暫存/工作區狀態。讀取已選官方發行通道，評估適用性並明確儲存結果；不能因為發現候選就安裝。報告實質變化、實際回執、下一條件與有用建議，不製造任務、不重複已完成歷史、不另建排程，也不傳送未授權的跨對話訊息。

已安裝的日常治理 Skill 提供具體方法。TaskCarry 本機記錄工具不自行喚醒 AI、不授予宿主權限，也不能用工具存在證明自然 heartbeat 已送達；其他宿主仍需各自的原生能力驗收。
