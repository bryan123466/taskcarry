# 返回原治理視窗的定時治理

[三步上手](windows-example.md) · [回饋範例](user-feedback-examples.md) · [技術合同](../GOVERNANCE_API.md)

標準接入在原治理視窗建立**每天兩個或三個時段**：一個早晨報告時段，加一到兩個吸收進展時段。治理先結合專案建議節奏，再確認你的時間與時區；復用相符調度，保持所選執行環境、模型和權限，不為安排自動化新增另一個治理寫入者。你仍可暫停或明確選擇手動使用；報告保留它與完整定時設定的差異。

## 兩類時段分別做什麼

| 時段 | 工作及使用者回饋 |
|---|---|
| 早晨報告 | 複核選定目前來源、事實、決定、依賴和健康，續辦授權內未完效果，檢查官方更新與恢復覆蓋，儲存實質變化，送達包含必要決定和下一步的簡明報告。 |
| 吸收進展 | 理解變化來源的修訂，保留證據與判斷，更新受影響工作台 view 並核對消費。無實質變化通常安靜結束；必要決定或真實失敗可提示，不重複已經送達的詢問。 |

每輪使用有界 `cycle`，保留原任務、擁有者與精確資源範圍。已觀察、已理解、已發布、已消費分別留證；中斷儲存原接續點。已知 issue/fix 核對適用性，記錄修正不等於已安裝。健康狀態需要近期證據，詢問跟進僅依據真實送達並按不同日期計算。

發現官方更新不授權安裝。私有傳輸按單獨選定的目標與範圍執行。本使用者專案的調度不會向 TaskCarry 開發者儲存庫發布產品，也不靜默向無關對話派發訊息。

## 四層證據分別驗收

| 證據 | 實際發生了什麼 |
|---|---|
| 設定回讀 | 每個時段綁定正確原視窗、cwd、每日時間/時區、啟用狀態、固定執行環境與完整提示詞雜湊。 |
| 自然觸發 | 該設定時段在真實到點時送達；手動測試另列。 |
| AI 執行 | 原對話 AI 讀取上下文、完成授權整輪並保留實際結果；僅收到提醒不證明執行。 |
| 報告送達 | 報告實際到達目標使用者位置，有送達回執；僅儲存內部結果檔案不算送達。 |

TaskCarry 產生精確調度計畫，由宿主原生工具建立和回讀。缺少宿主能力就保留具體接入缺口，不暗中換成作業系統定時器。執行環境需滿足所用宿主的可用條件；以目前工具是否暴露、實際執行為驗收事實，提示詞本身不能取得權限或喚起 AI。

`complete_governance_ready` 表示必需設定、首次整輪與恢復核驗通過；`natural_trigger_verified` 還要求各選定時段真實觸發並執行；`closed_loop_verified` 同時要求完整建制成立。報告時段須核對真實送達。等待首次自然觸發不是失敗，也不能編造證據補齊。

## 給治理的耐久指令

> 沿本原治理視窗、目前專案規則、工作台 view 與原任務繼續。保留明確擁有者/資源的有界整輪。只讀所選來源，理解修訂後更新事實、決定和依賴；續辦前核對實際效果。更新受影響入口時保留專業指令與 WIP，區分發布和消費。核對適用 issue/fix、證據健康、官方版本適用性及選定恢復覆蓋；無相應授權不安裝或上傳。儲存實質本機變化。報告時段送達簡明專案報告並記錄實際送達；吸收時段無變化則安靜結束。等待時保留原 cycle 和下一步，不重開完成歷史，不因同一天多次執行就重複追問。

實際設定使用已安裝 daily-governance Skill 與 `onboarding` 調度計畫產生的對應 profile 完整提示詞和雜湊；以上摘要不是驗收回執。[回饋場景](user-feedback-examples.md)展示應如何報告，[維護說明](governance-maintenance.md)說明更新與修復。
