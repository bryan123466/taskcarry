# 開始使用：把專案進度和工作視窗接起來

[接入主手冊](windows-example.md) · [日常操作索引](operation-manual.md) · [手動後備](manual-setup.md) · [English](../en/getting-started.md) · [简体中文](../zh-CN/getting-started.md)

已經在 Codex 中推進專案？保留專案與對話，TaskCarry 增加任務、成果、有效決定與接續位置的持久記錄。依你的情況選擇[首次安裝](windows-example.md)或[更新既有安裝](updating.md)。

<a id="準備目錄和兩項專案輸入"></a>

## 從現有專案出發

在獨立治理目錄建立治理視窗，已有有效 TaskCarry 治理視窗則重用。給出專案定位線索與選定產品的解壓縮位置，傳送[一條接入提示詞](windows-example.md#install)。它會安裝或重用工具、繼承既有工作，並帶著完成剩餘宿主操作；無需先學習 control ID、分支或指令。

空治理目錄不等於空業務專案。原成果、決定、任務身分與 WIP 繼續保留。確實是在 Codex 中啟動新專案時，同一對話也可以梳理目標並建立適當起點。

<a id="按需要加入專業視窗"></a>

## 保留有用的工作安排

治理先檢查既有視窗與職責。新增專業視窗可以為零，只有並行成果與清楚的寫入歸屬確有價值時才增設。繼續直接在原工作視窗推進；治理負責記憶與證據，長期專案協調是可選職責，不是使用條件。

宿主 AI 定向讀取獲准來源，不假設能夠存取所有舊對話。缺能力時給出目前準確一步；[手動後備](manual-setup.md)只在需要時提供指令與轉交提示詞。

## 接入後怎樣執行

可以要求繼續上次未完成任務、儲存有意義的暫停位置或查看已接入進度。工作視窗讀取自己的任務與相關有效決定，在工作節點儲存選定成果與下一步；理解候選與確認決定保持區分。共享進度不會自動合併所有程式碼。

接入結果應說明繼承的上下文、實際執行環境與逐視窗連線證據、目前清單與下一步。產生 MCP 檔案不代表原生工具已經載入。checkpoint、交付、接收、採用與業務驗收分別記錄。

排程任務、私有遠端及其他宿主/電腦均為可選項。再次返回時從記錄接續，不重新安裝或重複建立任務。完整路徑統一見[主手冊](windows-example.md)。
