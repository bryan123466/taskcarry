## 推薦的一條接入路線

為現有專案建立獨立治理視窗，已有有效 TaskCarry 治理視窗/control 則重用。傳送[一條接入提示詞](windows-example.md#install)，由治理繼承專案上下文、安裝或重用工具，並帶領完成剩餘連線；使用者不必先決定技術 ID 或專業視窗數量。

治理與記憶是預設職責。首次專案梳理幫助接入；臨時或長期專案協調由使用者選擇。繼續直接在原主視窗或專業視窗工作，調整協調偏好時保留同一記憶與任務身分。新增專業視窗可以為零。

助手讀取獲准的相關證據，說明缺失歷史；候選理解與建議不取代已確認的有效決定。空治理目錄不代表新業務專案，歷史成果與 WIP 保留在實際位置。

## 誰負責什麼

| 對象 | 職責 |
|---|---|
| 使用者 | 專案方向、業務決定、驗收及需要授權的動作。 |
| 治理視窗 | 維護專案記憶與證據，複核已接入進展，依計畫接收明確階段；依選擇兼任專案協調。 |
| 工作視窗 | 讀取相關有效決定、推進任務、儲存有意義的進展並精確交付穩定階段。 |
| 接收基準 | 用於接收階段的獨立乾淨 Git 工作區，不混入專業 WIP。 |
| TaskCarry 引擎 | 持久記錄、核對條件，執行已支援的儲存、接收、採用與恢復操作。 |
| 宿主 | AI 理解、實際對話讀取/建立、設定載入、權限與原生定時能力。 |

每個任務與寫入範圍保留一個主要寫入者；其他視窗可唯讀複核或承擔明確不重疊的子任務。對話分開不等於工作區已隔離，調整前檢查真實歸屬與活躍寫入者。

<a id="continuation"></a>

## 一次完整盤點與日常接續

工作視窗接續前讀取目前任務、相關最新檢查點與有效決定；在有意義的成果、決定變化或暫停處，儲存任務所屬的選定檔案、發現、來源與下一步。治理用這些記錄維護共同理解，只補讀有變化或缺失的相關上下文。舊對話存取能力另行核對，沒有自動全歷史監控。

用 `facts` 儲存帶來源身分的決定與關係，保留原始陳述、證據和單獨標明的 AI 判斷。顯式修訂保留先前有效事實，並指出受影響工作；它使用同一 Core 狀態，不建立競爭資料庫，也不靜默改掉原任務身分。

<a id="evidence"></a>

### 理解每種結果證明什麼

| 情況 | 相應記錄或操作 |
|---|---|
| 舊成果已在可信基準中 | 保留來源與納入事實，不再次排隊。 |
| 未完成或未提交工作 | 儲存 checkpoint 與準確接續點，不稱為交付。 |
| 穩定、明確的 Git 階段 | 核對 base、commit、任務與完整路徑，先預覽接收計畫再執行。 |
| 既有普通資料 | 保留選定檔案與來源；後續工作視窗仍完成標準 Git 設定。檢查點不提供通用非 Git 交付/接收。 |
| 暫停、等待或未變化任務 | 保留目前位置，不製造提醒或新積壓。 |
| 任務確需已接收程式碼 | 依實際相依需求預覽採用，保留本機提交/index/worktree/新檔案；只讀取進度無需合併。 |
| 操作中斷 | 核對實際效果與原身分，補齊支援的缺步。 |

地圖與說明描述專案，工具記錄與實際檔案證明效果。儲存、交付、接收、採用與業務驗收分別判斷，記錄素材路徑也不等於已驗證備份。

<a id="connection"></a>

## MCP、CLI 和定時治理的區別

MCP 讓宿主 AI 直接呼叫核心動作；原生工具不可用時，固定執行環境的隔離 CLI 繼續綁定同一 control。兩者均無需另設模型服務。接入檔案產生、宿主載入與原生 doctor/status 呼叫分別提供證據，各工作台核對自己的實際套件來源與綁定。

已登記工作台的 setup 可將四項 Skills 與接入資料寫到宿主工作目錄，仍綁定原 control。`target`、`workspace`、`task_id` 一起提供並依既有登記核對，不初始化第二 control。產生片段用隔離 UTF-8 啟動固定選定套件，合併生效設定時保留它；詳見[手動綁定與驗收](manual-setup.md#mcp)。

## 完整治理與原任務接續

`complete_v1` 清單包括持久專案/副本身分、選定來源的理解、實際任務/工作區/Git 綁定、每個視窗原生連線及準確工作台消費、本機治理 Git、首次有界整輪、獨立恢復演練、官方更新檢查，以及每天兩個或三個原視窗時段。這些是標準建制內容；私有遠端、網路硬碟和長期專案協調仍由使用者選擇。歷史參考對話保留來源證據，不虛構活躍工作區。

用 `context` 讀取原任務和目前 checkpoint，用 `facts` 保留帶來源身分的決定與關係，將證據和 AI 判斷分開。`cycle` 保留準確擁有者/資源、計畫效果、實際回執、來源階段、健康和下一步。`source_scan` 只分頁列舉授權本機中繼資料；正文由宿主另行讀取。精確參數集中在[治理 API](../GOVERNANCE_API.md)。

`workbench` 凍結帶來源版本的 view，產生準確私有入口計畫後發布，保留 Git HEAD/index 和無關 WIP。核對目前指標、原任務/視窗與來源是否變化；發布、複核過的消費證據、原生 doctor/status 分別成立。來源已經變化的舊 view 不能當目前事實。

`recovery` 按選定範圍擷取一致專案集、驗證位元組並在獨立目錄恢復為 standby。恢復回執列出 `disabled_host_files`：原宿主設定保留為證據，暫不作為恢復目標的活動設定，按新機器重新產生後再用。原專案身分加新副本身分不授權雙寫入；明確移交和真實原生驗收後才啟用。[恢復參考](remote-and-multicomputer.md)區分本機擷取、傳輸與真實第二宿主證據。

舊記錄保持可讀。`identity plan/execute` 顯式採用可遷移專案身分並保留舊來源別名，不暗中合併另一專案；`upgrade` 單獨維護衍生索引。舊驗收保留原 profile，新完整建制複核復用適用證據、補真實缺口，不改寫舊歷史。
