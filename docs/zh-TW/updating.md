# 更新與接續：保留原來的治理及工作

[首次安裝](windows-example.md) · [維護說明](governance-maintenance.md) · [技術合同](../GOVERNANCE_API.md)

## 先判斷你已有哪種治理

| 目前情況 | 如何接續 |
|---|---|
| 已安裝 TaskCarry | 繼續使用原治理目錄、任務及歷史；評估目前套件、能力方法與專案規則，只更新適用部分。 |
| 使用其他治理工具 | 先唯讀理解既有規則、決定、任務及儲存方式，確認哪些內容要接入 TaskCarry。保留原工具與資料；繼承資料不等於升級、解除安裝或自動遷移第三方系統。 |
| 只有一個治理對話 | 在原對話保留有效決定與未完成工作，補齊真實工作位置、專案記憶、本機儲存和工具連線；不要求重新講完所有歷史。需要獨立治理目錄時保留原對話來源。 |

不確定屬於哪一種時，在原治理對話傳送：

> 請先檢查我們現有的治理、工具及專案工作，告訴我屬於已有 TaskCarry 更新、其他治理工具接續，還是治理對話補齊設定。保留有效規則、決定、任務、歷史和未完成工作，不重新初始化既有專案。按你讀到的 TaskCarry 接入方法，提供最小必要的接續計畫，帶我完成缺少的步驟，並說明實際完成結果。

只有治理對話、尚無產品時，先按[首次安裝的目錄準備](windows-example.md)取得套件；由治理讀取目前工作目錄下 toolkit 的產品入口。若有多個可疑狀態來源，先說明差異再選擇，不建立第二份狀態來掩蓋不明確的綁定。

## 從其他工具或治理對話接續

先確認專案及允許讀取的範圍，再繼承有來源的目標、成果、決定、職責及未完成位置。工具介面能讀到什麼、歷史讀取了多少，都應明確。需要你轉交舊視窗資訊時，只提供最小交接提示詞。

治理隨後按三步手冊補齊本機 Git、實際工作位置、同一治理來源的連線、首次治理、恢復驗證及原對話日常排程。原有工具不受 TaskCarry 套件更新支配；確需跨系統遷移、停用或替換時，另給具體方案，不把這類動作混入一般接入。

## 已安裝 TaskCarry：在原治理視窗完成更新

繼續使用原治理目錄和視窗。需要升級 TaskCarry 時，可傳送下面的維護提示詞：

> 按我選擇的通道檢查已登記的官方發行來源。我提供產品包時先核對精確身分。比較發行說明、實際執行包、已安裝 Skills/方法和我的專案規則，說明適用變化、相容性及最小必要更新。發現新版本不等於授權安裝。
>
> 在本次已授權更新範圍內，保留原 control/source 身分、任務、檢查點、事實、決定、視窗、自訂設定、Git 暫存區和未完成工作。包變更使用獨立候選執行環境，保留可恢復的舊安裝。先預覽精確受管檔案/設定修改，保全自訂內容，再逐個核驗受影響原生連線。
>
> 用完整建制 profile complete_v1 對照既有證據。保留舊驗收記錄及其原含義，不把舊記錄改名冒充新 profile。復用仍適用證據，補齊身分、來源理解、工作台消費、首次整輪、恢復演練和日常時段設定缺口。舊專案仍用本機路徑身分時，先給明確 identity 計畫再採用，保留舊來源別名及記錄。不為刷新記憶初始化另一 control 或合併業務分支。
>
> 調整調度前保留有效原綁定，與我核對一個報告加一到兩個吸收時段的準確安排，不重複建立。自然觸發、原對話 AI 執行和實際報告送達分別驗證。中斷先查已有效果，只補缺步。最後報告改變了什麼、什麼仍可繼續、驗證結果、排除項和目前真正必要的一步。

治理日常讀取已登記官方通道。離線表示遠端狀態未知；內容沒變不重複維護。穩定版或候選版依你的明確通道選擇；同版本名但包雜湊不同，需要身分複核。

Core 更新、能力/方法更新和使用者專案決定分別管理。公開發行、本機安裝、受管檔案發布、執行中宿主載入是不同回執。

中斷後說：**「繼續原 TaskCarry 更新，核對已完成效果，只完成剩餘計畫。」** 版本差異放在[發行說明](../RELEASE_0.2.0rc9.md)，預期結果見[回饋範例](user-feedback-examples.md)，確有缺步才用[手動後備](manual-setup.md)。

## 更新時如何確認記憶接續

讓原治理視窗核對原任務、決定、來源及最新檢查點。在獨立候選環境和授權的狀態副本上，完成整專案備份、清單校驗與獨立目錄恢復，檢查選定產物及歷史關係；恢復副本先保持待機。需要明確索引更新時，核對原證據保留。使用者不需要修改資料庫標記或重新初始化專案。

治理方法、專案規則和 Core 包分別評估。某個候選包不適用時，繼續使用已驗證的執行組合，說明受影響功能與下一條件；無關治理優化和專業工作可以繼續。換包、受管設定更新、原生視窗載入及本機問題消除分別報告。回退必須保留切換後的新增事實，舊資料庫不能直接覆蓋目前記錄。

## 發現新版後，使用者會收到什麼

治理會先說明這次更新對目前專案的用途，再給出具體維護方案，請你選擇現在維護、安排稍後或略過。確認後保留原專案記憶與工作視窗，分別核驗安裝和原生載入。完整過程及可給原治理的接續提示見[RC8 維護流程補充](core-update-maintenance.md)。
