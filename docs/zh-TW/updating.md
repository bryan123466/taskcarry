# 更新既有 TaskCarry

[首次安裝](windows-example.md) · [English](../en/updating.md) · [简体中文](../zh-CN/updating.md)

回到這個專案原有的治理視窗，傳送下面這段話。治理會核對目前安裝，判斷需要更新哪些部分，並帶著完成其餘操作；你的專案與工作視窗繼續使用。

## 傳給原治理視窗

> 請協助這個專案更新 TaskCarry。從 https://github.com/bryan123466/taskcarry/releases 核對最新公開版本（包括預發布）；如果我已經提供產品包，請先核對並使用該包。閱讀所選產品包的更新指南與 taskcarry-project-setup Skill 中的更新方法，再判斷需要執行的操作。
>
> 先核對既有安裝、專案記錄與未完成操作，閱讀更新說明，判斷這次更新是否適用。沿用原治理目錄、任務、檢查點與工作視窗，保留我的檔案、設定修改與未完成工作。
>
> 在本次更新範圍內，請準備合適的更新內容，簡要說明影響，再完成你可以代辦的更新與檢查。只更新確實需要變更的部分；不需要更新時直接告訴我結果，不重新安裝或接手專案。
>
> 如果需要我完成宿主確認或重新載入，只給我目前必要的一步，填好位置與內容。我回覆完成後，請繼續核對實際連線與原專案能否接續。
>
> 最後用簡短清單告訴我：更新了什麼、原工作是否保留、現在是否可繼續使用，以及還有沒有需要我做的一步。

## 更新時會發生什麼

治理從原專案繼續工作，按需要處理工具套件、專案接入材料與宿主連線。你不用手動比較版本號、選 wheel 檔案或逐項複製設定。

如果只需要更新文件，就直接使用更新後的說明；需要替換工具套件時，由助手透過宿主提供的安裝能力完成。TaskCarry 本身沒有另一個「一鍵修補」指令。遇到設定衝突，治理會保留現場並說明具體需要決定的內容。

## 中途停下後

回到原視窗說：**「繼續剛才的 TaskCarry 更新，先核對已經完成的部分。」** 治理會從儲存的進度繼續；僅剩重新載入時不會讓你重新安裝。
