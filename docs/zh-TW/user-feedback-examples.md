# 使用者回饋範例：USB 資料擷取與曲線顯示工具

[三步操作手冊](windows-example.md) · [三層架構](architecture.md) · [English](../en/user-feedback-examples.md) · [简体中文](../zh-CN/user-feedback-examples.md)

假設你已在 Codex 中開發一個小工具：裝置透過 USB 序列埠傳送讀值，電腦顯示曲線並匯出 CSV。你已有韌體、電腦軟體和模擬驗證的工作對話，還有一份舊的硬體與介面討論。TaskCarry 要把這些工作接在同一份專案記憶上，讓各視窗知道共同約定和下一步。

**下文對話是合成的產品回饋範例，不是你的專案或某個宿主已通過驗收的報告。** 隨套件提供的[可執行模擬資料](../../examples/complete-governance/README.md)可驗證文字解析與資料重播；它沒有連接真實裝置、燒錄韌體或繪製實際使用者介面。真正報告須引用當次證據，不能照抄範例中的成功結論。

## 先把專案說清楚

本例先約定 UTF-8 文字一行一筆訊框：`READ,42,1000,1.234`，行尾為換行符號。它依序表示「讀值」、序號 42、模擬裝置時間 1000 毫秒、模擬值 1.234。第一階段先把「產生資料 → 解析 → 曲線顯示 → CSV 匯出」串起來，再驗證斷線和重連；無線連線留待後續。

| 專業職責 | 這階段要做什麼 | 怎樣看出完成 |
|---|---|---|
| 韌體與協定 | 確認欄位意義，提供穩定的模擬讀值與文字訊框 | 給同一份輸入，接收端能按共同格式重現結果；尚不表示板卡韌體通過測試。 |
| 電腦軟體 | 解析訊框，把讀值送入曲線，並匯出 CSV | 輸入三筆，曲線對應三個點，CSV 的序號、時間和值與輸入一致；實際介面和檔案操作需各自驗證。 |
| 模擬驗證 | 重播正常、斷線、重連 | 正常值可核對；斷線不產生假資料；重連不重複舊點、不接上斷線前的半筆資料。 |

這是三種職責，不要求每個使用者必須開三個專業視窗；既有視窗可以合併承擔。舊硬體說明只是讀取來源，不因此宣稱它是已接入的活躍視窗。真實取樣、驅動程式、USB 時序和量測準確度仍需實物測試。

## 1. 總控先說明理解與接入範圍

> 我理解你要做的是一個 USB 資料擷取與曲線顯示工具。第一階段先用模擬資料跑通流程：韌體側提供約定的讀值訊框，電腦側解析、顯示並匯出，驗證側檢查正常與中斷恢復。
>
> 我看到你已有韌體與協定、電腦軟體、模擬驗證的工作對話，建議保留它們；如果目前只有兩個視窗，可以把協定與模擬放在同一視窗，不必為了安裝而拆分。舊硬體與介面討論只作為參考來源。這個範圍以你選定的對話和材料為準。
>
> 我會保留「先模擬、再接實物」和「本階段不做無線連線」的有效決定。你仍可直接在專業視窗推進。我負責記錄決定、核對依賴，並把共同協定的變化送回相關視窗；長期專案協調由你選擇。

如果只是看到了標題和目錄，總控應明確說「這是候選範圍，還沒讀到具體內容」。選定範圍後再讀取正文；宿主沒有讀取對話的工具時，改用原視窗給出的最小交接，不把目錄掃描當作已經理解專案。

## 2. 接入後給出能繼續做事的安排

> 選定的工作視窗已連接同一治理。原任務、檔案、未提交變更和專業說明都保留了，各視窗分別核對了自己的實際連線與目前入口。
>
> 共同資料格式已經明確，但電腦端的曲線與 CSV 還沒有完成驗證。下一步請韌體與協定視窗儲存穩定的三筆模擬輸入；電腦軟體視窗用這份輸入接通解析、曲線和匯出；模擬視窗先檢查正常資料，再做斷線與重連。介面舊筆記保留為參考，沒有被登記成新工作任務。

這裡應該看得到「誰繼續什麼、用什麼材料、怎麼驗證」。設定好了治理，並不代表上述工程任務已經做完。

## 3. 第三步的完整設定報告

以下範例假設必要設定、第一次治理和獨立恢復演練均已實際通過：

> **USB 資料擷取專案的治理設定已完成。** 你可以繼續在原來的視窗開發。第一次治理已統一模擬協定、確認每個視窗目前的位置，並保留尚未完成的曲線與匯出工作。

| 視窗或來源 | 職責 | 接下來做什麼 |
|---|---|---|
| 治理總控 | 專案記憶、規則同步、儲存恢復與定時治理 | 跟進協定與電腦實作是否一致，把有意義的變化回饋給相關視窗。 |
| 韌體與協定 | 模擬讀值、訊框格式與欄位解釋 | 儲存共同輸入；真實韌體與裝置測試另行安排。 |
| 電腦軟體 | 解析、即時曲線與 CSV | 用共同輸入完成介面與匯出驗證。 |
| 模擬驗證 | 正常、斷線和重連重播 | 檢查資料與顯示結果，給出可重現的差異。 |
| 舊硬體與介面筆記 | 參考來源 | 保留已確認約定，不作為活躍工作視窗。 |

> 各活躍視窗已分別完成原生工具連線驗收並讀到自己的工作入口。本機 Git 已儲存選定治理檔案；原業務儲存庫和未提交工作保留。以後可先儲存進度，再對明確檔案形成精確版本；儲存進度不等於已交付或已被接受。
>
> 恢復演練涵蓋了選定專案狀態、物件、協定材料、驗證腳本、Git 歷史與暫存/未暫存變更。獨立恢復的副本保持待機。未儲存的編輯器內容和平台私有對話歷史不在這份恢復集內，憑證另行管理；本例未選擇網路硬碟，因此沒有聲稱已上傳異地。
>
> 已核對官方更新來源；有新版本時先判斷適用性，不自動安裝。你確認的時區下，已設定一個上午報告時段和一個下午吸收進展時段，均回到原治理對話。設定已回讀，首次自然觸發尚待發生；我不會把本次手動執行當作定時閉環已驗收。
>
> 現在建議回電腦軟體視窗，用三筆輸入接通曲線與 CSV。治理建立完成，工程開發繼續；真實 USB 裝置尚未測試。

若缺少必要視窗的連線、本機儲存、定時設定或恢復驗證，報告應說「設定進行中」，列出準確缺口和目前操作。不能把套件已安裝寫成治理全部完成，也不要求你從頭重裝。

## 4. 正常推進後，總控怎樣彙報

共同輸入為：

```text
READ,42,1000,1.234
READ,43,1100,1.250
READ,44,1200,1.220
```

下面是完成相應檢查後才可以給出的回饋：

> 三筆模擬資料已得到相同的序號、時間和值。解析與重播檢查通過，送給曲線的輸入是 1000、1100、1200 毫秒處的三個點；CSV 參考列也與它們一致。本次驗證了資料流程，實際曲線介面和檔案匯出操作仍分別列出證據，不用解析通過代替。
>
> 斷線後，解析器沒有產生新量測值，並清除了未完成的半筆資料；重連後繼續讀取遞增序號，舊序號沒有重複寫入。接下來由電腦軟體視窗驗證真實介面的斷線提示和顯示恢復。硬體接入仍是後續階段。

隨套件重播程式能驗證上述模擬解析、斷線/重連和 CSV 數值保真；它不是完整電腦軟體。若真實裝置重新啟動會把序號歸零，需要另定工作階段或重啟標記，不能直接套用「序號持續遞增」的模擬假設。真實報告引用具體輸入、輸出和測試結果；靜態曲線截圖也不能代替真實介面互動。

## 5. 遇到缺口、中斷或沒有變化

> 電腦軟體視窗的設定檔已寫好，但該視窗還沒有出現 TaskCarry 原生工具。請信任並重新載入報告列出的那個目錄。我會隨後核對該視窗的實際連線；已完成的協定視窗設定保留，不重裝、不重新登記任務。

> 中斷前，協定視窗的入口已寫入，只缺回執。我核對檔案效果後補齊了回執。另一個視窗的檔案後來被你修改過，已保留，下一步依據新內容準備計畫；其他獨立工作可繼續。

> 本次吸收已讀的來源沒有實質變化，原有進度與下一步保留，沒有新建交付、安裝或重開已完成任務。未能讀取的來源單獨列為待核對。

吸收時段無變化可安靜儲存，由上午報告彙總。來源未讀到不是「沒有變化」，也不因此編造成功或失敗。

## 6. 恢復與異地並行

> 已依清單把選定協定、腳本、專案記憶與 Git 變更恢復到獨立位置，並核對恢復結果。它仍屬於原專案，但目前是待機副本；新位置的連線還須重新驗收。
>
> 如果在另一台電腦繼續電腦端開發，可使用獨立工作分支，把精確版本、修改檔案、驗證結果和下一步交回同一個治理。若要把治理本身遷過去，先確認舊寫入者停止，再核對新宿主並執行明確的移交；不能讓兩個副本同時改同一份治理狀態。

本機獨立目錄恢復、上傳、異地下載、真實第二台電腦接入與治理移交分別報告。沒有第二台機器的實測，就不能聲稱異地全流程已驗收；這些也都不構成真實 USB 裝置驗證。
