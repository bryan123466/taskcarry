# 首次安裝：三步建立完整的專案治理

[更新與接續](updating.md) · [手動後備](manual-setup.md) · [回饋範例](user-feedback-examples.md) · [無人機專案實例](../../examples/vision-drone-governance/README.md) · [English](../en/windows-example.md) · [简体中文](../zh-CN/windows-example.md)

這份手冊面向已經用 Codex 推進專案的人。建立一個獨立的治理視窗，由它整理專案記憶、接入既有工作，並帶你完成設定。你仍然可以直接在原來的對話中工作；是否長期讓治理同時協調專案，由你選擇。

## 1. 打開治理資料夾，傳送一條提示詞

建立本機 `TaskCarry` 資料夾，把[完整產品套件](../../START_HERE.md#download)解壓縮到 `toolkit/`，保留套件內版本目錄。在 Codex 中開啟外層 **TaskCarry 資料夾**並建立獨立對話。原有業務檔案維持原位置。

（如果已安裝 TaskCarry、使用其他治理工具或已有治理對話，需要更新或接續，請參閱[更新與接續入口](updating.md)。）

```text
TaskCarry/                 在 Codex 中開啟的治理工作目錄
  toolkit/                 解壓縮後的產品套件
```

**直接複製下面的完整提示詞，無需填寫產品路徑：**

> 請讀取目前工作目錄下 toolkit 中的 TaskCarry 產品入口和接入 Skill，帶我建立專案治理。先檢查既有治理、安裝和工作狀態，保留原有規則、決定、任務及未完成工作。
>
> 先唯讀整理目前工具可見的對話索引，提出可能的專案及包含的對話，讓我選擇；選定後再讀取相關歷史。為我準備原視窗的完整接入提示詞，並按實際需要建議新增視窗。
>
> 隨後依實際工作目錄復用本機 Git、MCP 和 Skills，讓同目錄中的原對話各自保留任務身分，不為接入要求每個對話另建目錄。協助完成專案記憶、首次治理及恢復驗證。與我確認時間及時區後，設定日常治理和官方更新檢查。需要我操作時，一次只給目前必要的一步，寫明按鍵或入口、準確目錄、用途及完成後回覆什麼。新連線尚未載入時，先備好設定和原對話的專案關聯，再帶我集中重新啟動一次 Codex，返回原對話逐窗驗收；已驗收成功的連線不重複重新啟動。中斷後繼續缺少的步驟。
>
> 最後告訴我已經接入哪些視窗、分別負責什麼、還有哪些缺項，以及接下來建議做什麼。我仍然可以直接在原來的工作視窗推進。

產品目錄就是 `toolkit/` 中的 TaskCarry 套件，由助手從目前目錄核對。讀取套件讓助手了解治理方法；**你的專案內容來自隨後選定的對話與檔案**。套件缺失、內容不完整或有多份無法區分的套件時，助手才說明具體問題。

## 2. 由治理帶著完成接入和第一次治理

接下來只需跟隨治理提供的目前一步。它先告訴你這次可讀取哪些對話索引、是否包含封存、是否還有下一頁，以及哪些範圍無法存取；再整理候選專案，供你選擇。索引包含標題、目錄等線索，只有在你確認專案範圍後，才讀取相關歷史內容。你也可以直接指定專案，跳過無關候選。

選定後，治理應依序完成：

| 你會收到什麼 | 治理負責完成什麼 |
|---|---|
| 專案理解與接入建議 | 整理原成果、有效決定、任務及未完成位置；區分既有事實與建議。舊參考對話可以僅作資料來源。 |
| 每個視窗的具體操作 | 為原視窗提供已填好目標與內容的接入提示詞；確需新增職責時，再給建立位置、完整啟用提示詞及預期回執。視窗數量依專案需要決定。 |
| 需要你參與的目前一步 | 準備真實工作目錄、本機 Git、專案設定和 MCP。信任目錄、登入或重載由宿主要求決定；治理說明去哪裡操作、成功會看到什麼，再繼續核驗。 |
| 接入與首次治理結果 | 逐視窗確認實際連線、原任務及目前入口；整理共同記憶，精確儲存選定檔案，檢查官方更新，完成本機恢復演練。 |
| 日常節奏建議 | 與你確認時間及時區後，建立或復用返回原治理對話的報告和進度整理時段，並讀回實際設定。 |

**既有對話不用重新建立，也不要求每個對話單獨建目錄。** 多個原對話可以共用既有業務目錄及其連線設定，各自保留原任務、檢查點及記憶入口。只有並行寫入確實需要隔離時，治理才建議獨立 Git 工作樹。

若原對話的目錄還沒有在 Codex 中開啟並信任，治理先核對並寫明其準確原目錄，再帶你做這一小段操作：

1. 在目前 Windows Codex 中按 **Ctrl+O**；其他介面使用「開啟／新增專案資料夾」入口。
2. 選擇治理提供的**原工作目錄**，開啟這個既有目錄。此時**不用新增對話，也不用複製檔案**。
3. 若出現信任提示，核對是該目錄後確認。
4. 回到治理對話，回覆「已開啟指定目錄，並確認了出現的信任提示」；沒有出現提示則如實說明。治理會核對設定和原對話的專案關聯。
5. 治理確認本次各目錄準備完成、需要載入新連線後，先儲存正在進行的工作，**結束並重新開啟 Codex 一次**。可以等本次所有目錄準備好後一起重新啟動，不必每開啟一個目錄就重新啟動。
6. 回到**原治理對話**回覆「已重新啟動」，並回到各個**原工作對話**完成治理提供的驗收提示。保留原歷史、任務和檔案，不重新安裝或建立替代對話。

這些操作讓宿主登記並信任原目錄，**將原對話關聯到該專案並載入其中的連線設定**，仍使用同一份治理記憶。治理依宿主能力完成關聯，核對實際工作目錄沒有改變，再逐窗原生呼叫 `taskcarry_doctor`、`taskcarry_status`，核對版本、來源、control、原任務和最新檢查點。這條 Windows Codex 接入路線在新連線、目錄信任和對話關聯準備好後，明確安排一次重新啟動，再回原對話驗收。已實際驗收成功的連線略過重新啟動；其他宿主採用其支援的載入方式。側欄出現對話或重新啟動完成本身都不代替原生驗收。[查看已填目錄的回饋範例](user-feedback-examples.md#open-existing-project)。

未掛在專案下的活躍對話，先核對它實際使用的目錄與工具，優先保留原對話並依宿主能力關聯該目錄。這個標籤本身不表示不能使用 MCP，傳送提示詞也不會改變視窗目錄。僅作歷史參考的對話可只登記為來源，無需為原視窗設定 MCP 或 Git。若宿主無法讀取所需歷史或完成連線、排程，治理只給目前缺步及續辦方法，必要時連結[手動後備](manual-setup.md)。

本機版本儲存、工作視窗連線、恢復驗證、日常治理設定及官方更新檢查屬於標準建制。私有 Git 遠端與網路磁碟可隨後依你的選擇設定；未選擇它們不影響本機治理。發現新版後先判斷是否適用，不會因此自動更換執行套件。

發現適用的官方 Core 更新時，治理先準備保全、設定和重新啟動方案，再詢問是否維護；未變或已暫緩的候選不重複追問。見[官方更新與維護閉環](core-update-maintenance.md)。

## 3. 複核完成報告，按原習慣繼續工作

治理應提供一份容易理解的報告：

- **理解了什麼：** 專案目標、繼承的決定與成果、仍需確認的內容。
- **接入了哪些視窗：** 每個視窗的職責、原任務、實際工作位置與連線結果。
- **完成了哪些設定：** 本機儲存、專案記憶、恢復驗證、官方更新檢查及日常時段的實際結果。
- **還缺什麼：** 具體缺步、影響範圍與目前必要操作。未完成項不會被寫成「已完成」。
- **下一步怎麼做：** 回到哪些原視窗繼續什麼工作；哪些建議由你決定。

「設定已完成」與「自然排程閉環已驗證」分開報告。時段設定讀回後，仍要等它真正到點，再核對原治理 AI 是否執行、是否完成儲存及是否送達報告。某一步等待宿主操作，不應抹掉其他已經完成的結果。

之後你可以在原專業視窗說「繼續上次未完成的任務」，或在治理視窗說「檢查目前專案進度」。中斷時說「保留已完成的結果，繼續剩餘設定」，不必從第一步重來。
