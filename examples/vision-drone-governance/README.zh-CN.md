# 从零散对话到可运行的无人机仿真项目

[English](README.md) · [繁體中文](README.zh-TW.md)

[打开完整仿真实例](simulation/README.zh-CN.md)：图像驱动的离线应用、算法、硬件工程资料、独立测试和产品演示。[六个聊天的原生验收](simulation/evidence/native-acceptance.json)与浏览器测试、自然调度分别列证。[早期固定事件阶段](native-case/README.zh-CN.md)保留原成果与当时的证据边界。

软件窗口已经画过演示界面，算法窗口提出了障碍事件，硬件窗口整理过相机、计算板与飞控的关系。它们最初没有统一里程碑和接口。治理继承这些工作，将原聊天接入共同项目记忆，再按需要建议增加产品和独立测试职责。包含治理在内共六个聊天；测试与治理共用目录，但各自保留任务和入口。

交付的是**图像驱动的避障仿真原型**：生成图像的像素进入规则检测器，检测结果驱动 9 × 9 离散二维场景中的移动。三个场景覆盖无障碍、固定障碍和断帧后恢复，页面支持暂停、重置及 JSON 导出。硬件交付为工程资料；训练模型、飞行动力学、真实接线与实飞不在已验范围。

## 用户在过程中会看到什么

| 时点 | 项目情况 | 治理做的事 |
| --- | --- | --- |
| 接入前 | 软件提出 `frame_id/label/region`；算法想加置信度与时间戳；硬件关注采集时刻。 | 读取用户选中的旧讨论，保留成果、有效决定与未完成位置。 |
| 选择项目 | 用户选择把这个无人机项目接入治理。 | 说明理解的目标和疑问，沿用三个原窗口，随里程碑扩展建议产品/推广和独立测试职责。 |
| 建立治理 | 六个聊天分别负责不同工作，两个聊天共用目录。 | 接入同一 control，保留原任务与本地版本保存，分别核对连接与当前入口消费。本次 Windows 实测的四个专业窗口在信任项目并重启 Codex 后通过。 |
| 调整范围 | 用户决定第一阶段只做室内离线演示。 | 保留此前探索历史，将新范围和统一接口送到四个专业窗口。 |
| 继续推进 | 软件改界面，算法对齐案例，硬件收敛边界，推广说明同步。 | 分别核对“入口已写入”和“专业对话实际读过并处理”的证据。 |
| 可运行原型 | 检测器读取图像像素，软件执行和导出三个场景，独立测试在单独副本验收。 | 对齐合同、精确交付、工程边界与宣传依据。重新定位的公开副本通过 5 项算法、9 项浏览器和 10 项软件验证。 |
| 中断或恢复 | 某项工作还没完成，或需要独立恢复副本。 | 沿原 checkpoint 和精确计划续办；恢复任务、文件和 Git 历史，副本先保持待接管。 |

户外评估保留为暂停任务。软件、算法、硬件的原任务身份继续存在，不会因为装了治理就重新开始。

旧讨论可能从未用过 TaskCarry。这时接入会为原有工作建立稳定的任务记录，并关联原对话和成果；如果已有 TaskCarry 任务，就沿用它的身份。本地确定性回放预先登记合成任务，因此还能检查已有任务与 checkpoint 的关联是否保留。

## 本地回放会做什么

在独立环境安装候选 wheel，使用该环境的 Python 3.11+ 解释器，并准备 Git。`-I` 避免当前源码目录覆盖安装包。选择一个不存在或空的合成目录，在本示例目录执行：

```text
python -I replay.py /path/to/empty-drone-demo
python -I replay.py /path/to/empty-drone-demo --execute
```

第一条只显示计划；第二条执行计划。把目的地换成自己选好的合成目录。脚本不连接真实项目、原生对话、调度器、网络或飞行硬件。

完成后会出现下面的结构，这些目录由回放生成：

```text
empty-drone-demo/
  TaskCarry/               合成项目记忆和本地 Git 历史
  workspaces/
    software/              保留的软件资料和未完成稿
    algorithm/             保留的算法资料和未完成稿
    hardware/              保留的硬件资料和未完成稿
    product/               新增的产品/推广职责
  recovery-media/          选定状态、文件和 Git 恢复对象
  restore-controller/      独立恢复控制器
  standby/                 恢复副本，尚未成为写入者
  REPLAY_REPORT.json       实际回放结果及证据边界
```

对应测试还会制造单个工作台写入中断，以及恢复已经落盘但最后回执丢失的情况。验证先查实际效果、沿同一计划补缺步；原有暂存与未暂存工作、任务历史及 checkpoint 都需要保留。

本地回放证明其支持范围内的任务、文件、Git 与恢复行为。完整仿真及六个真实聊天的原生回执，分别为各自层次补充具时点证据。自然调度、实体飞行、生产采用和多电脑接管仍不能由此推定。

治理方法还包含按需准备替代聊天：旧窗口停止写入后，沿原任务与已保存成果继续。[受控接续演练](simulation/continuity/README.zh-CN.md)已完整完成：替代算法聊天核验自己的原生连接与当前入口，新增完成三帧像素阈值／连通性检查，并把证据交回治理吸收；旧窗口只读确认交接，原任务、已保存成果和 Git 状态保留。[独立审阅](simulation/testing/public-product-review.md)已通过当时的 50 文件公开产品副本；随后统一 LF 的字节须另核清单。该方法不代表修复宿主压缩或找回未保存上下文。详见[证据说明](EVIDENCE.md)。
