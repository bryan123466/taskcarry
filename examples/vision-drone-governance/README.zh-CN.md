# 四个对话怎样推进同一个无人机项目

[English](README.md) · [繁體中文](README.zh-TW.md)

[查看真实合成对话的成果](native-case/README.zh-CN.md)：保留的原始工作、共同接口、可打开的离线页面和四个专业角色的证据。原生 MCP 加载与自然调度仍分别列明验收状态。

软件窗口已经画过演示界面，算法窗口提出了障碍事件，硬件窗口整理过相机、计算板与飞控的关系。每个窗口都有成果，却还没有统一第一阶段要完成什么、接口怎么对齐。TaskCarry 帮治理窗口继承这些成果，整理共同记忆，让原窗口沿着原任务继续；缺少产品表达时，再建议补一个产品/推广窗口。

这个合成项目以**图像识别避障无人机**为方向，第一阶段收敛为**室内固定障碍的离线演示**。示例展示如何形成产品轮廓和治理协作，不把演示当成已经完成模型训练或真实飞行。

## 用户在过程中会看到什么

| 时点 | 项目情况 | 治理做的事 |
| --- | --- | --- |
| 接入前 | 软件提出 `frame_id/label/region`；算法想加置信度与时间戳；硬件关注采集时刻。 | 读取用户选中的旧讨论，保留成果、有效决定与未完成位置。 |
| 选择项目 | 用户选择把这个无人机项目接入治理。 | 说明理解的目标和疑问，沿用三个原窗口，建议补产品/推广职责。 |
| 建立治理 | 四个窗口有各自职责和实际工作目录。 | 接入同一个 control，保留原任务，建立本地版本保存，并分别核对连接。 |
| 调整范围 | 用户决定第一阶段只做室内离线演示。 | 保留此前探索历史，将新范围和统一接口送到四个专业窗口。 |
| 继续推进 | 软件改界面，算法对齐案例，硬件收敛边界，推广说明同步。 | 分别核对“入口已写入”和“专业对话实际读过并处理”的证据。 |
| 中断或恢复 | 某项工作还没完成，或需要独立恢复副本。 | 沿原 checkpoint 和精确计划续办；恢复任务、文件和 Git 历史，副本先保持待接管。 |

户外评估保留为暂停任务。软件、算法、硬件的原任务身份继续存在，不会因为装了治理就重新开始。

旧讨论可能从未用过 TaskCarry。这时接入会为原有工作建立稳定的任务记录，并关联原对话和成果；如果已有 TaskCarry 任务，就沿用它的身份。本地确定性回放预先登记合成任务，因此还能检查已有任务与 checkpoint 的关联是否保留。

## 本地回放会做什么

在独立环境安装候选 wheel，使用该环境的 Python 3.11+ 解释器，并准备 Git。`-I` 避免当前源码目录覆盖安装包。选择一个不存在或空的合成目录，在本示例目录执行：

```text
python -I replay.py /path/to/empty-drone-demo
python -I replay.py /path/to/empty-drone-demo --execute
```

第一条只显示计划；第二条执行计划。把目的地换成自己选好的合成目录。脚本不连接真实项目、原生对话、调度器、网络或飞行硬件。

完成后会出现下面的结构，这些目录由回放生成：

```text
empty-drone-demo/
  TaskCarry/               合成项目记忆和本地 Git 历史
  workspaces/
    software/              保留的软件资料和未完成稿
    algorithm/             保留的算法资料和未完成稿
    hardware/              保留的硬件资料和未完成稿
    product/               新增的产品/推广职责
  recovery-media/          选定状态、文件和 Git 恢复对象
  restore-controller/      独立恢复控制器
  standby/                 恢复副本，尚未成为写入者
  REPLAY_REPORT.json       实际回放结果及证据边界
```

对应测试还会制造单个工作台写入中断，以及恢复已经落盘但最后回执丢失的情况。验证先查实际效果、沿同一计划补缺步；原有暂存与未暂存工作、任务历史及 checkpoint 都需要保留。

这能证明本地治理记录和文件/Git/恢复的实际行为。某个对话是否理解了资料、原生 MCP 是否接通、自然自动化是否按时触发，以及无人机是否能工作，都需要各自的真实证据，不能从脚本成功推出来。
