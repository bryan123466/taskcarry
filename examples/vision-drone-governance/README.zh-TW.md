# 從零散對話到可執行的無人機模擬專案

[English](README.md) · [简体中文](README.zh-CN.md)

[開啟完整模擬實例](simulation/README.zh-TW.md)：影像驅動的離線應用、演算法、硬體工程資料、獨立測試與產品展示。[六個對話的原生驗收](simulation/evidence/native-acceptance.json)與瀏覽器測試、自然排程分別列證。[早期固定事件階段](native-case/README.zh-TW.md)保留原成果與當時的證據邊界。

軟體視窗已經畫過展示介面，演算法視窗提出了障礙事件，硬體視窗整理過相機、運算板與飛控的關係。它們最初沒有統一里程碑與介面。治理繼承這些工作，將原對話接入共同專案記憶，再按需要建議增加產品與獨立測試職責。包含治理在內共六個對話；測試與治理共用目錄，但各自保留任務和入口。

交付的是**影像驅動的避障模擬原型**：生成影像的像素進入規則偵測器，偵測結果驅動 9 × 9 離散二維場景中的移動。三個場景涵蓋無障礙、固定障礙與斷幀後恢復，頁面支援暫停、重設及 JSON 匯出。硬體交付為工程資料；訓練模型、飛行動力學、真實接線與實飛不在已驗範圍。

## 使用者在過程中會看到什麼

| 時點 | 專案情況 | 治理做的事 |
| --- | --- | --- |
| 接入前 | 軟體提出 `frame_id/label/region`；演算法加入信心分數與時間戳；硬體關注擷取時刻。 | 閱讀使用者選中的舊討論，保留成果、有效決定與未完成位置。 |
| 選擇專案 | 使用者選擇將這個無人機專案接入治理。 | 說明理解的目標與疑問，沿用三個原視窗，隨里程碑擴展建議產品／推廣及獨立測試職責。 |
| 建立治理 | 六個對話分別負責不同工作，兩個對話共用目錄。 | 接入同一 control，保留原任務及本機版本保存，分別核對連線與目前入口消費。本次 Windows 實測的四個專業視窗在信任專案並重新啟動 Codex 後通過。 |
| 調整範圍 | 使用者決定第一階段只做室內離線示範。 | 保留先前探索歷史，將新範圍與統一介面送到四個專業視窗。 |
| 繼續推進 | 軟體改介面，演算法對齊案例，硬體收斂邊界，推廣說明同步。 | 分開核對「入口已寫入」與「專業對話實際讀過並處理」。 |
| 可執行原型 | 偵測器讀取影像像素，軟體執行與匯出三場景，獨立測試在單獨副本驗收。 | 對齊合約、精確交付、工程邊界與宣傳依據。重新定位的公開副本通過 5 項演算法、9 項瀏覽器及 10 項軟體驗證。 |
| 中斷或恢復 | 某項工作尚未完成，或需要獨立恢復副本。 | 沿原 checkpoint 與精確計畫續辦；恢復任務、檔案與 Git 歷史，副本先保持待接管。 |

戶外評估保留為暫停任務。軟體、演算法、硬體的原任務身分持續存在，不會因安裝治理而重新開始。

舊討論可能從未使用 TaskCarry。這時接入會為原有工作建立穩定任務紀錄，連結原對話與成果；如果已有 TaskCarry 任務，就沿用原身分。本地確定性重播預先登記合成任務，因此也能檢查既有任務與 checkpoint 關係是否保留。

## 本地重播會做什麼

在獨立環境安裝候選 wheel，使用該環境的 Python 3.11+ 解譯器，並準備 Git。`-I` 避免目前原始碼目錄覆蓋安裝包。選擇不存在或空白的合成目錄，在本案例目錄執行：

```text
python -I replay.py /path/to/empty-drone-demo
python -I replay.py /path/to/empty-drone-demo --execute
```

第一條僅顯示計畫，第二條執行計畫。將目的地換成自己選好的合成目錄。腳本不連接真實專案、原生對話、排程器、網路或飛行硬體。

完成後由重播產生的結構如下：

```text
empty-drone-demo/
  TaskCarry/               合成專案記憶與本地 Git 歷史
  workspaces/
    software/              保留的軟體資料與未完成稿
    algorithm/             保留的演算法資料與未完成稿
    hardware/              保留的硬體資料與未完成稿
    product/               新增的產品／推廣職責
  recovery-media/          選定狀態、檔案與 Git 恢復物件
  restore-controller/      獨立恢復控制器
  standby/                 恢復副本，尚未成為寫入者
  REPLAY_REPORT.json       實際重播結果與證據範圍
```

測試另外製造單一工作台寫入中斷，以及恢復已落盤但最後回執遺失的情境，驗證先查實際效果、沿同一計畫補缺步，並保留原有暫存與未暫存工作、任務歷史及 checkpoint。

本機重播證明其支援範圍內的任務、檔案、Git 與恢復行為。完整模擬與六個真實對話的原生回執，分別為各自層次補充具時點證據。自然排程、實體飛行、生產採用及多電腦接管仍不能由此推定。

治理方法也包含按需準備替代對話：舊視窗停止寫入後，沿原任務及已儲存成果繼續。[受控接續演練](simulation/continuity/README.zh-TW.md)已完整完成：替代演算法對話核驗自己的原生連線與目前入口，新增完成三幀像素閾值／連通性檢查，並將證據交回治理吸收；舊視窗唯讀確認交接，原任務、已儲存成果與 Git 狀態保留。[獨立審閱](simulation/testing/public-product-review.md)已通過當時的 50 檔公開產品副本；後續統一 LF 的位元組須另核清單。此方法不代表修復宿主壓縮或找回未儲存上下文。詳見[證據說明](EVIDENCE.md)。
