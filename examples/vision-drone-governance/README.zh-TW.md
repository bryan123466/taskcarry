# 四個對話如何推進同一個無人機專案

[English](README.md) · [简体中文](README.zh-CN.md)

軟體視窗已經畫過示範介面，演算法視窗提出了障礙事件，硬體視窗整理過相機、運算板與飛控的關係。各視窗都有成果，卻還沒統一第一階段要完成什麼、介面怎麼對齊。TaskCarry 協助治理視窗繼承這些成果，整理共同記憶，讓原視窗沿原任務繼續；缺少產品表達時，再建議補一個產品／推廣視窗。

這個合成專案以**圖像識別避障無人機**為方向，第一階段收斂為**室內固定障礙的離線示範**。案例展示如何形成產品輪廓與治理協作，並不代表模型訓練或實際飛行已完成。

## 使用者在過程中會看到什麼

| 時點 | 專案情況 | 治理做的事 |
| --- | --- | --- |
| 接入前 | 軟體提出 `frame_id/label/region`；演算法加入信心分數與時間戳；硬體關注擷取時刻。 | 閱讀使用者選中的舊討論，保留成果、有效決定與未完成位置。 |
| 選擇專案 | 使用者選擇將這個無人機專案接入治理。 | 說明理解的目標與疑問，沿用三個原視窗，建議補產品／推廣職責。 |
| 建立治理 | 四個視窗各有職責與實際工作目錄。 | 接入同一個 control，保留原任務，建立本地版本保存，分別核對連線。 |
| 調整範圍 | 使用者決定第一階段只做室內離線示範。 | 保留先前探索歷史，將新範圍與統一介面送到四個專業視窗。 |
| 繼續推進 | 軟體改介面，演算法對齊案例，硬體收斂邊界，推廣說明同步。 | 分開核對「入口已寫入」與「專業對話實際讀過並處理」。 |
| 中斷或恢復 | 某項工作尚未完成，或需要獨立恢復副本。 | 沿原 checkpoint 與精確計畫續辦；恢復任務、檔案與 Git 歷史，副本先保持待接管。 |

戶外評估保留為暫停任務。軟體、演算法、硬體的原任務身分持續存在，不會因安裝治理而重新開始。

舊討論可能從未使用 TaskCarry。這時接入會為原有工作建立穩定任務紀錄，連結原對話與成果；如果已有 TaskCarry 任務，就沿用原身分。本地確定性重播預先登記合成任務，因此也能檢查既有任務與 checkpoint 關係是否保留。

## 案例材料

- 合成起始討論：[軟體](initial/software.md)、[演算法](initial/algorithm.md)、[硬體](initial/hardware.md)；建議新增的職責：[產品／推廣](initial/product-brief.md)。
- [場景與範圍](scenario.json)：原任務、早期構想、目前里程碑、保留的決定與後續範圍。
- [真實對話驗證腳本](NATIVE_CHAT_RUNBOOK.zh-CN.md)：先形成零散討論，再走主手冊三步驟，最後驗證一次範圍變更。這是操作說明，不是宿主動作已發生的證明。
- [成果與證據說明](EVIDENCE.md)：應產生哪些有用的專案檔案，以及如何區分種子、腳本重播與原生對話成果。
- [可執行本地重播](replay.py)：實際呼叫共享核心，驗證任務記憶、工作台發布、Git 保存與恢復。

首次安裝仍依主操作手冊的三步驟進行。本案例提供直觀的完成效果，不要求使用者為安裝 TaskCarry 另外做一個無人機專案。

## 本地重播會做什麼

在獨立環境安裝候選 wheel，使用該環境的 Python 3.11+ 解譯器，並準備 Git。`-I` 避免目前原始碼目錄覆蓋安裝包。選擇不存在或空白的合成目錄，在本案例目錄執行：

```text
python -I replay.py /path/to/empty-drone-demo
python -I replay.py /path/to/empty-drone-demo --execute
```

第一條僅顯示計畫，第二條執行計畫。將目的地換成自己選好的合成目錄。腳本不連接真實專案、原生對話、排程器、網路或飛行硬體。

完成後由重播產生的結構如下：

```text
empty-drone-demo/
  TaskCarry/               合成專案記憶與本地 Git 歷史
  workspaces/
    software/              保留的軟體資料與未完成稿
    algorithm/             保留的演算法資料與未完成稿
    hardware/              保留的硬體資料與未完成稿
    product/               新增的產品／推廣職責
  recovery-media/          選定狀態、檔案與 Git 恢復物件
  restore-controller/      獨立恢復控制器
  standby/                 恢復副本，尚未成為寫入者
  REPLAY_REPORT.json       實際重播結果與證據範圍
```

測試另外製造單一工作台寫入中斷，以及恢復已落盤但最後回執遺失的情境，驗證先查實際效果、沿同一計畫補缺步，並保留原有暫存與未暫存工作、任務歷史及 checkpoint。

這能證明本地治理紀錄和檔案／Git／恢復的實際行為。對話是否理解資料、原生 MCP 是否接通、自然自動化是否按時觸發，以及無人機是否能運作，都需要各自的真實證據，不能由腳本成功推定。
