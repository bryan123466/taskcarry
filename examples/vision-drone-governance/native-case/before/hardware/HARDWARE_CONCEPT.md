# 视觉识别与避障无人机硬件／固件概念

本阶段范围是虚构项目的桌面合成链路。用合成帧代替摄像头输出，在计算单元形成视觉识别与障碍提示，再由监控软件展示。真实供应商选型、采购、烧录、真实飞控接入和试飞均在本阶段范围外。

## 概念连接

```mermaid
flowchart LR
    camera["摄像头角色（合成帧源）"] -->|合成帧| capture["采集适配层"]
    capture -->|图像和采集元数据| compute["计算单元（桌面进程）"]
    compute -->|识别结果与链路状态| monitor["监控软件"]
```

| 环节 | 首轮联调职责建议 | 需要约定的接口 |
| --- | --- | --- |
| 摄像头角色 | 回放带帧级标注的合成序列，模拟画面交付和输入中断 | 与算法确认室内外光照场景、输入尺寸、帧率、像素格式与行步长。 |
| 采集适配层 | 承担采集侧固件职责。校验帧格式，分配帧标识，记录采集时刻，通过有界队列交付图像，统计积压和丢帧。 | 与算法约定图像缓冲区的持有与释放时机、时间戳透传及过载处置。 |
| 计算单元 | 按模型需要预处理，生成与源帧关联的识别结果和障碍提示。可先注入脚本结果，验证接口和监控状态。 | 与算法确认模型输入、类别、置信度及框坐标的含义。与软件确认空结果、处理失败和丢帧的表达。 |
| 监控软件 | 按帧关联结果和时序信息，显示障碍提示、链路状态与延迟。 | 与软件确认事件载荷与本机传递方式、乱序和断流时的显示规则。若需要显示叠框，再约定预览帧来源和坐标回映。 |

## 采集时间提案

硬件／固件侧建议在合成帧交给采集适配层时打时间戳，打点在进入等待队列之前。计算单元在结果事件中原样携带源帧标识和 `capture_time`。建议用运行标识与帧号关联同一次回放中的帧和结果，重启后切换运行标识。

首轮测量建议让采集与监控使用同一单调时钟基准。监控若在收到事件时打点，所报的是「采集至接收」延迟，计算为接收时刻减去采集时刻。若需要「采集至显示」延迟，由软件另外定义显示打点。采集时间缺失或时钟基准无法对齐时，延迟显示为不可用。可另记计算开始和结果发布时刻，定位排队或处理造成的等待。

字段名称、时钟来源与单位、跨进程对齐、回放打点、缺失值和事件传递方式均待算法与软件确认。

## 资源口径

以下为桌面合成回放假设，详见 [资源约束表](CONSTRAINTS.csv)。假设输入帧为 **640 × 480 像素、RGB24、15 帧/秒**，按行紧密排列。每帧有 `640 × 480 × 3 = 921,600 B` 原始像素数据，连续交付的原始数据量为 `13,824,000 B/s`。假设等待队列最多容纳 **3 帧**，待处理原始帧最多占 `2,764,800 B`。计算中的帧、预处理副本、模型工作内存和监控缓存须计入各自的峰值。事件载荷及可选预览另行计量。

首轮需要记录队列峰值、丢帧数、处理耗时、CPU 占用和峰值内存。算法提供预处理及推理的测量口径，软件提供事件大小和实际发布频率。过载时的取舍、延迟验收值和资源预算上限均待联调确认。

室内外光照、目标图像尺寸及目标帧率仍待确认。室外导航／定位保留为后续议题，见 [决策记录](DECISIONS.md)。
