# 首轮桌面联调准备

当前停在概念设计。下一步先约定合成输入和事件样例，再用桌面回放核对帧关联、时序与状态显示。

## 联调前要对齐的事项

- [ ] 硬件／固件与算法确认室内外各需覆盖的光照条件、目标画面尺寸、帧率、像素格式、行步长与缩放约定。提交一段带帧级标注的合成序列，含有障碍标注及无障碍标注的帧。
- [ ] 硬件／固件与算法确认帧标识的作用范围、缓冲区何时释放，以及队列满时如何处理并记录被丢弃的帧。
- [ ] 算法与软件对齐一份事件样例，列出帧标识、候选障碍输出、坐标口径、空结果和错误。确认监控是否需要预览及如何关联同一帧。
- [ ] 硬件／固件与软件确认 `capture_time` 提案的打点、时钟基准、单位和缺失值，选定采集至接收或采集至显示的延迟口径。算法确认结果生成时保留源帧时间。

## 建议用回放核对的行为

| 合成用例 | 待验证的行为与记录 |
| --- | --- |
| 正常回放 | 能按帧查到候选障碍、用于比对的合成标注和结果事件。完整处理后的空结果有明确显示。记录处理耗时、CPU 占用、峰值内存和事件载荷。 |
| 计算积压、超出队列容量 | 可从帧号、队列峰值及丢帧记录追溯缺失结果。回放结束且队列清空后，核对收到的帧数与已完成、已丢弃和处理失败的帧数之和。 |
| 时间戳缺失或时钟基准不匹配 | 显示延迟不可用。同一时钟基准的样例可按约定的两处打点重算延迟。 |
| 输入暂停并恢复 | 按待定断流判据显示链路状态，恢复后将提示关联到对应的源帧。需补齐异常状态和恢复规则。 |
