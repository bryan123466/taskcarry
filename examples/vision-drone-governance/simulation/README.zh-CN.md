# 从零散聊天到可运行的避障仿真原型

[English](README.md) · [繁體中文](README.zh-TW.md)

这份实例展示 TaskCarry 如何把已有软件、算法和硬件聊天接入同一个治理记忆，保留原任务，再补上产品演示与独立测试角色，协作交付一个可本地运行的视觉避障仿真。你可以直接[打开应用入口](app/index.html)，或先看[产品演示路线](product/DEMO_ROUTE.md)。GitHub 文件页只展示源码；下载完整产品包后，在桌面 Chrome 中打开这个 HTML 文件即可运行，无需服务器或网络。

## 亲自运行

1. 打开 `app/index.html`，选择「空房间到达」「固定障碍绕行」或「缺帧等待与恢复」。
2. 点击「开始」，观察实际生成的相机像素、检测框、运行路线和逐拍记录。可以暂停、继续和重置。
3. 点击「导出 JSON」，保存本次检测、动作、位置、链路与终态。每个场景从重置运行两次会产生相同的逻辑记录。

这是二维合成图像与网格运动仿真。视觉算法采用可检查的颜色和连通区域规则，硬件交付是工程方案与预算。实物接线、真实相机、飞控动力学、真实飞行及训练模型均未验证。算法确实读取生成的像素；控制器从检测结果选动作。改变前方格像素后，检测和动作会随之改变。

## 治理是怎样参与的

原先分散的技术聊天分别保留了接口草案、算法计划和硬件约束。治理先让用户选择项目范围，继承这些资料和原任务，再明确一次可交付的离线仿真目标。原窗口承担各自专业工作；新增独立测试在同一治理目录内使用不同任务和真实聊天路由。TaskCarry 负责记住决定、来源、依赖和停点，把公共接口与当前任务入口发布给对应窗口，并核对每个窗口自己的读取与回执。

| 角色 | 实际交付 | 治理核对的依赖 |
| --- | --- | --- |
| 软件 | 六文件离线应用、相机渲染、界面、逐拍执行和日志 | 集成算法的精确文件，按同一接口合同执行 |
| 视觉算法 | 从真实 RGBA 缓冲提取检测，依据检测选择动作 | 空帧、缺帧、坏帧和像素 A/B 输入输出 |
| 硬件工程 | 模块、接线方案、接口时序、预算与待测清单 | 估算使用同一帧规格，物理参数保留待测 |
| 独立测试 | 独立副本的 Chrome 操作、实际下载和失败恢复探针 | 被测文件摘要一致，逐项结果可复验 |
| 产品与演示 | 介绍、使用说明、演示路线与逐条表述证据 | 以通过的具体检查约束公开介绍 |
| 治理 | 共同目标、版本决定、任务分工、接口与验收标准 | 回执来自实际专业窗口，公开发行另行核对 |

三步安装的主线仍是建立独立治理对话、依治理的提示完成接入、拿到验收与下一步。这个实例把步骤背后的协作和产物展开给你看，不要求使用者手动复制这里的内部文件树。原窗口加入 Codex 项目并加载 MCP，不等于重新建立一个接续聊天。当前 Windows 验证中，专业目录已配置并信任后，用户重启 Codex 才使四个原窗口的原生 MCP 调用成功；每个窗口仍需自己核对连接。

随后完成的[按需聊天接续演练](continuity/README.zh-CN.md)让原算法窗口受控停写，在已有且受信任的项目中建立接续聊天，沿用原任务并完成新的三帧像素边界验证。治理核对了返回成果及旧窗口的只读回报。这次验证的是受控交接，没有制造宿主崩溃或声称找回未保存的上下文，也没有预先创建空白备用窗口。

## 独立复验

先复制本目录到临时验证位置。应用本身只需浏览器；自动检查额外需要 Node.js 24 与本机 Chrome。可通过 `RC8_CHROME_PATH` 指定浏览器可执行文件，脚本也支持操作系统默认位置。浏览器使用单独的临时配置，不接触日常 Chrome 配置。

在复制后的目录运行：

```sh
node algorithm/verify-algorithm.cjs INTERFACE_CONTRACT.json
node testing/prepare-public-handoff.mjs
```

第二条命令先核对公开文件清单，生成仅本次运行使用的本地路径交接，再由独立验证脚本复制应用并实际操作 Chrome。结果、下载、截图和像素探针写入 `testing/local/`，保留随包的历史记录。软件自测另可运行 `node verify-software.mjs`，结果写入 `local/`。自动验证脚本只属于这个示例，TaskCarry Core 的运行条件仍是 Python 标准库与按需 Git。

[独立公开产品复核](testing/public-product-review.md)已对所列确切50文件对象给出通过结论。此后发行导出统一文本为LF、重算相关公开引用，并加入复核摘要、导航链接与单独留证的接续案例；这些差异单独记录，不把旧对象的通过冒称为后来新增内容已审。应用、合同、验证脚本和固定技术快照保持已验字节。
