# 從零散對話到可執行的避障模擬原型

[English](README.md) · [简体中文](README.zh-CN.md)

這份實例展示 TaskCarry 如何將原有軟體、演算法及硬體對話接入同一份治理記憶，保留原任務，再加入產品示範與獨立測試角色，共同交付可在本機執行的視覺避障模擬。可以先看[應用入口](app/index.html)或[示範流程](product/DEMO_ROUTE.md)。GitHub 檔案頁只顯示原始碼；下載完整產品包後，在桌面 Chrome 開啟 HTML 檔即可執行，不需要伺服器或網路。

## 親自執行

1. 開啟 `app/index.html`，選擇空房間到達、固定障礙繞行或缺幀等待與恢復場景。
2. 按「開始」，觀察實際生成的相機像素、偵測框、路線及逐拍紀錄。可以暫停、繼續和重設。
3. 匯出 JSON，保存偵測、動作、位置、連線與終態。同一場景從重設執行兩次，會得到相同的邏輯紀錄。

應用介面與原始工程報告使用簡體中文。這是二維合成圖像與網格運動模擬；視覺基線採用可檢查的顏色與連通區域規則，硬體交付為工程方案及預算。實物接線、真實相機、飛控動力學、實際飛行與訓練模型尚未驗證。偵測器確實讀取像素緩衝，控制器依偵測結果選動作；只改變前方格像素，偵測與動作便會隨之改變。

## 治理如何參與

原本分散的技術對話各自保存介面草稿、演算法計畫及硬體限制。治理先請使用者選擇專案範圍，繼承原任務及決定，再確定可交付的離線模擬目標。原對話繼續專業工作；新增的獨立測試對話共用治理目錄，以不同任務及真實對話路由運作。TaskCarry 保存決定、來源、相依關係及停點，將共用介面與當前入口發布給各對話，再核對它們各自的讀取及回執。

| 角色 | 實際交付 | 治理核對的相依關係 |
| --- | --- | --- |
| 軟體 | 六檔離線應用、畫面生成、介面、逐拍執行與紀錄匯出 | 精確演算法檔案及同一介面契約 |
| 視覺演算法 | 從 RGBA 像素偵測障礙並選擇動作 | 空幀、缺幀、壞幀與像素 A/B 結果 |
| 硬體工程 | 模組、接線、時序、預算及待測清單 | 相同畫面規格，估算與實測分開 |
| 獨立測試 | 獨立副本中的 Chrome 操作、實際下載與失效探針 | 精確檔案摘要與可重現觀察 |
| 產品示範 | 介紹、使用說明、示範路線與表述證據 | 以通過的具體檢查支持文案 |
| 治理 | 共同目標、版本決定、分工、介面及驗收標準 | 真實專業回執，公開發行另行核對 |

上手流程仍為三步：建立治理對話、依治理指引完成接入、取得驗收報告及下一步。本例展開背後的協作與產物，不要求使用者手動複製所有內部檔案。將原對話歸屬 Codex 專案並載入 MCP，不等於重建接續對話。在這次 Windows 驗證中，專業目錄完成設定與信任後，使用者重新啟動 Codex，四個原對話的原生 MCP 呼叫才成功；每個對話仍須自行驗收連線。

之後完成的[按需對話接續演練](continuity/README.zh-TW.md)讓原演算法視窗受控停寫，在既有且受信任的專案建立接續對話，沿用原任務並完成新的三幀像素邊界驗證。治理核對返回成果與舊視窗的唯讀回報。本次驗證的是受控交接，沒有製造宿主當機或聲稱找回未保存的上下文，也未預先建立空白備用視窗。

## 獨立複驗

先複製本目錄到暫存位置。應用只需瀏覽器；自動檢查另需 Node.js 24 與本機 Chrome。可用 `RC8_CHROME_PATH` 指定瀏覽器，未指定時依作業系統尋找。測試使用獨立暫存瀏覽器設定，不改日常設定。

在複製後的目錄執行：

```sh
node algorithm/verify-algorithm.cjs INTERFACE_CONTRACT.json
node testing/prepare-public-handoff.mjs
```

第二條命令先核對公開清單，產生只供本輪使用的本機路徑交接，再用獨立副本操作 Chrome。結果、下載、截圖與像素探針存入 `testing/local/`，保留隨包歷史證據。另可執行 `node verify-software.mjs`，結果存入 `local/`。這些額外依賴屬於示例驗證；TaskCarry Core 仍使用 Python 標準函式庫及按需 Git。

[獨立公開產品複核](testing/public-product-review.md)已對所列確切50檔案物件給出通過結論。之後發行匯出統一文本為LF、更新相關公開引用，並加入複核摘要、導覽連結與單獨留證的接續案例；差異單獨記錄，不把舊物件通過當成後續新增內容已審。應用、契約、驗證腳本與固定技術快照保留已驗位元組。
