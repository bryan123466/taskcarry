# 聊天无法继续时，让原任务在新聊天里接着推进

无人机视觉算法已经完成，软件也集成了确切的检测器。此时，如果原算法聊天无法继续，是否只能换个窗口从头解释项目？这个接续演练把原算法窗口受控转为停写状态，由治理按需建立一个接续窗口，让它沿用原任务、原目录、原检查点和已确认的算法，继续一项具体的边界验证。

这次没有故意触发 Codex 崩溃或上下文压缩故障。我们模拟的是旧聊天不能再承担写入工作，验证项目记忆能否在窗口之外保存、交接并继续产生结果。也没有预先建立空白备用窗口：需要接续时，才在已有且受信任的项目里创建新聊天。

## 治理先保住什么

原算法窗口结束自己发起的验证并保存停写回执。治理核对宿主回合已结束、没有该窗口仍在执行的写入任务，再记录原目录的 Git HEAD、索引、已保存文件及未提交改动。此前完成的算法、原检查点和旧对话都保留。

随后，治理给同一算法任务发布一份交接说明：旧窗口保留历史并只读；新窗口核验入口后负责本次新增验证。新窗口使用真实聊天身份匹配路由，读取同一 control 和原任务，自己调用原生 MCP 并登记已读入口。一次配置或治理替它写一份“已接入”文字，不能代替这次实际读取。

本案例只有一份可执行检测器，位于[应用代码](../app/detector.js)。接续窗口将它当作只读输入，不复制一套新算法再把结果混在一起，也不重新初始化项目。

## 给接续窗口的下一步是具体工作

待办是检查检测器的「至少 16 个像素、四连通」规则。治理给出同一份[接口合同](../INTERFACE_CONTRACT.json)，新窗口独立编写验证脚本，送入三张 160×120 RGBA 合成图像。三帧的元数据、背景和算法完全相同，只有指定像素不同。

| 输入 | 要验证的边界 | 预期结果 |
| --- | --- | --- |
| A：一个 3×5 的箱体色矩形，共 15 个像素 | 少于阈值 | 有效帧，零检出 |
| B：给 A 增加一个与矩形共边的箱体色像素 | 连通区域达到 16 个像素 | 恰好一个箱体，像素数为 16 |
| C：给 A 增加一个仅在角上相接的箱体色像素 | 同色总数为 16，但四连通分量为 15 与 1 | 有效帧，零检出 |

这项工作检验的是新窗口能否依据已有决定和代码继续完成一个新的、可复现的任务。它同时保留输入摘要、真实检测结果、运行命令以及冻结算法的前后摘要。实际结果见[边界验证](boundary-evidence.json)与[复现脚本](verify-boundary.cjs)。

## 目前已经做到哪里

| 环节 | 实际状态 |
| --- | --- |
| 原窗口停写、原任务与原目录保留 | 已有停写回执，治理已核对 |
| 新窗口按需建立，实际项目和目录核对 | 已完成 |
| 两个窗口对应同一原任务的入口发布 | 已完成，旧入口和历史回执保留 |
| 新窗口自己的原生连接、读取和消费 | 已完成并保存本窗口原生回执，见[连接摘要](native-acceptance.json) |
| 三帧边界实验及原文件保全 | 三帧均通过；原文件与 Git 状态保留 |
| 旧窗口再次读取交接并保持只读 | 旧窗已只读回读交接与新成果，未重跑或新增消费 |
| 治理核对并保存新结果 | 已完成；原任务与检查点保留，核验摘要已保存 |

[接续证据](continuity-evidence.json)记录了这次有限演练的完成结果。治理已交叉核对新窗口自身消费、三帧通过结果、旧窗口只读回报、原 Git 状态及四份历史配置前像。原业务任务仍停在原有 waiting 检查点，没有把这次核验当成整个项目验收。旧窗口按要求没有新增 Core 消费记录：其 `NOT_VERIFIED` 消费状态，与已完成的宿主只读回报分别记录。

## 用户会收到怎样的指引

下面是这次方法的用户侧表达，不是已经执行过的逐字聊天引用：

> 原算法工作已经保存在项目目录，原任务和检查点会继续沿用。我先确认旧窗口及其后台写入已停止，再整理本次交接。请在已经使用的算法项目中建立一个新聊天；原聊天保留作历史参考，不需要重新安装产品或搬走原文件。新聊天确认自己的 MCP、原任务和当前入口后，将继续完成那项 16 像素边界验证。它交回结果后，我会把新增证据纳入项目记忆。旧窗口如果恢复，先读交接并保持只读，避免两边重复写同一份工作。

需要用户确认宿主信任、打开项目或重启时，治理应给出确切目录和有限操作；已完成并验证的步骤不重复。任务的下一步应来自真实成果与检查点，不能靠猜测补出失去的聊天内容。

这项能力可概括为：**聊天换了，已经保存的项目记忆、任务身份和成果可以接着用。** 它不修复宿主本身，不保证找回未保存或从未读到的上下文。当前 TaskCarry 的路由负责指引正确的任务入口；单写入者依赖实际停写和职责交接，不是对旧聊天文件权限的强制封锁。

```sh
node continuity/verify-boundary.cjs
```

复制 simulation 目录后，用 Node.js 24 执行。可移植脚本只读冻结应用与合同，新结果只写入 `continuity/local/`。它复现像素边界检查，不重新执行宿主聊天交接。
