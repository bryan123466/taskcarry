# RC8 室内视觉避障仿真原型计划

操作者确认本轮为「完整仿真原型与工程资料，暂不接真实硬件」。沿用合成无人机项目和治理任务 `rc8-governance`。原三个技术窗口、产品窗口以及既存任务、检查点和入口保留。`rc8-indoor-replay-v1` 是完成的合成事件回放案例。v2 另用 `rc8-drone-sim-v2` 版本和目录。 [v1 项目复核](../../native-case/governance/PROJECT_REVIEW.md)

## 最小可交付原型

在桌面 Chrome 本地打开 `app/index.html` 即可选择场景、启动、暂停、重置。场景选择对应空房间到达、固定障碍绕行、缺帧与恢复三个任务。页面展示局部模拟相机的实际生成像素及检测框、地图路线、碰撞或到达状态，并可导出 JSON 逐拍日志。资源随包携带，运行不依赖外部服务。

仿真器渲染 `160×120 RGBA8` 的北向俯视局部帧。视觉基线按固定合成颜色和连通区域从像素提取框。控制器根据检测、位置、目标和到访计数选择一格移动或保持。仿真器独立判断移动、碰撞、到达。三个确定性场景在 `9×9` 网格上按 `100 ms` 的逻辑间隔推进。逻辑时钟是本轮设计选择。相机模型、像素规则、消息及预期轨迹以同一份合同为准。 [接口合同](../INTERFACE_CONTRACT.json)

独立测试需要用相同的帧号、姿态和目标重放两次，仅改变前方单元格的像素。检测须由空变为箱体，命令须由向北变为向东。场景真值用于渲染和仿真器动作后的碰撞判定，检测和控制调用的输入及测试据此核对。该基线展示合成图像处理和闭环仿真，可解释性来自固定规则及逐拍日志。

## 职责与输出

原专业窗口仅在各自的 `outputs/rc8-drone-sim-v2/` 新增本轮成果。独立测试复用治理目录，使用 `outputs/rc8-drone-sim-v2/testing/` 保存自己的测试和证据。

| 窗口和任务 | 本版交付 | 接续依赖 |
| --- | --- | --- |
| 软件 `drone-software-monitor` | `app/` 可离线运行的浏览器仿真、`SOFTWARE_RUN.md`、`software-evidence.json`。实现帧生成、逐拍执行、界面和日志导出。 | 用合同固定输入。集成算法窗口交付的确切脚本并记录摘要。 |
| 视觉算法 `drone-vision-events` | `detector.js`、`controller.js`、`ALGORITHM_BASELINE.md`、`algorithm-evidence.json`。实现像素检测与有限的确定性控制。 | 先与软件对齐两项调用签名和实际空帧、缺帧。 |
| 硬件方案 `drone-hardware-concept` | `HARDWARE_ENGINEERING.md`、`INTERFACE_WIRING_PLAN.md`、`RESOURCE_BUDGET.csv`。含模块、接口、时序、资源预算、接线规划和将来的实测清单。 | 按合同区分仿真接口、算术估计与待验证的物理参数。本轮为文档方案。 |
| 独立测试拟用 `drone-independent-test` | `TEST_REPORT.md`、`test-evidence.json` 及独立复现所需的脚本和数据。 | 由主工作台在同一治理项目创建真实测试聊天并回传身份。使用已交付的精确软件与算法文件。 |
| 产品与演示 `drone-product-demo` | `PRODUCT_INTRO.md`、`DEMO_ROUTE.md`、`USER_GUIDE.md`、`product-claims.json`。 | 用独立测试通过项及工程资料约束文案，并在同一离线包复演。 |
| 原治理 `rc8-governance` | 版本决定、接口和验收约定、同目录接入方案及各原窗口的证据汇总。 | 核对具体输入、产物版本和原生回执，保留待办。 |

## 交付顺序与状态

1. 主工作台转交四份原窗口提示词，并在现有治理项目目录创建独立测试聊天，回传真实 `thread_id` 和实际 `cwd`。 [独立测试创建与激活提示词](../README.zh-CN.md)
2. 软件与算法按合同并行实现，软件将通过自身核对的确切输入、算法文件和离线应用交独立测试。硬件资料可并行完成。发现合同差异时保留实际样本和检查 ID，由治理核对后更新版本。
3. 独立测试验证确定性、像素因果、空帧、丢帧恢复、碰撞终止、浏览器操作及导出。产品文稿引用通过的具体检查。 [验收计划](ACCEPTANCE_PLAN.md)
4. 原治理已通过本窗口的原生 `doctor`、`status` 读回候选运行时与原 control。四个专业原窗及拟新增测试窗各自需要真实回执。同目录任务路由单独验收。 [原治理原生回执](../README.zh-CN.md)
5. 主工作台负责现有 TaskCarry GitHub 仓库的精确发布。待独立测试和原生缺项收口后，由主工作台从候选中脱敏选取浏览器包、原字节合同、运行指南、算法说明、工程资料、用例及必要证据。公开材料使用相对链接，附版本和摘要，从独立目录再走一次三种场景及日志导出。

当前交付为计划和接续提示词。六窗口原生接入与 v2 仿真完成度依照实际回执更新。
